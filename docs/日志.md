# 日志（cboot.log）

`cboot.log` 对标 Logback 的核心模型：

| Logback | cboot |
|---|---|
| `Logger` | `logging::logger` |
| Appender | `logging::sink` |
| Encoder / Layout | `logging::layout` |
| `RollingFileAppender` | `logging::rolling_file_sink` |
| MDC | `logging::context` |
| `logback.xml` | `log.*` 配置 |

模块名是 `cboot.log`，命名空间是 `logging`（全局 `log` 与 C 数学函数
`double log(double)` 冲突）。

## 1. 基础包与组件

```text
cboot.log        日志 API + 默认 console 实现，随 SDK 安装，始终可用
log_component    可选：读取 log.* 配置，安装 console/file sink、级别覆盖
```

不选 `log_component` 时：

```cpp
import cboot.log;

auto log = logging::get("todo");
log.info("hello {}", 42);       // console, info
```

选 `log_component` 后，`LogSetup` 在 `PostConstruct` 读取配置：

```cpp
class App : public application<App> {
    using components = type_list<log_component>;
};
```

## 2. API

```cpp
auto log = logging::get("todo.api");

log.trace("...");
log.debug("...");
log.info("server listening on {}:{}", host, port);
log.warn("...");
log.error("...");

if (log.enabled(logging::level::debug))
    log.debug("expensive {}", compute());
```

- 使用 `std::format`，类型安全
- `logger` 只保存名称，按名称前缀匹配级别覆盖
- `logging::root()` 是根 logger
- 全局配置（启动期）：`set_level`、`set_layout`、`add_sink`、
  `clear_sinks`、`set_logger_level`、`flush`

## 3. 配置

```json
{
  "log": {
    "level": "info",
    "format": "text",
    "pattern": "%d %-5level [%thread] %logger - %msg%n",
    "output": "both",
    "file": "logs/app.log",
    "max_size_mb": 10,
    "max_files": 5,
    "file_level": "debug",
    "logger_levels": [
      "cboot.web=debug",
      "cboot.auth=warn",
      "todo=debug"
    ]
  }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `level` | `info` | 根级别：trace/debug/info/warn/error/off |
| `format` | `text` | `text` / `json` |
| `pattern` | `%d %-5level [%thread] %logger - %msg%n` | text 模式 |
| `output` | `console` | `console` / `file` / `both` |
| `file` | 空 | 文件路径；output 为 file/both 时必填 |
| `max_size_mb` | `10` | 0 表示不轮转 |
| `max_files` | `5` | 保留的备份数；0 表示轮转时截断 |
| `file_level` | 空 | 文件 sink 阈值；空表示不额外限制 |
| `logger_levels` | 空 | `"名称=级别"`，按前缀匹配，最长前缀优先 |

级别过滤是“根级别 + 最长前缀覆盖 + sink 阈值”的交集。

## 4. Pattern

text layout 支持：

```text
%d          2026-11-23 10:12:24.579（UTC）
%level      级别（大写）
%-5level    左对齐，宽度 5
%logger     logger 名称
%msg        消息
%thread     线程 id
%n          换行
%X{key}     MDC 字段
```

不支持 Logback 的 lookups、颜色、脚本、JNDI。

## 5. Sink 与轮转

- `console_sink`：trace/debug/info → stdout，warn/error → stderr
- `file_sink`：追加写，目录不存在时自动创建
- `rolling_file_sink`：按大小轮转
  ```text
  app.log → app.log.1 → app.log.2 ...
  ```
- 文件 sink 每行 flush；日志失败不会影响业务
- 时间使用 UTC

## 6. MDC

```cpp
{
    logging::context::scope ctx("request_id", request_id);
    log.info("handling request");
}
```

- 线程本地，离开作用域恢复旧值
- text 用 `%X{request_id}` 输出
- JSON layout 把 MDC 字段平铺到对象中

## 7. 框架接入

- `cboot.app`：启动/停止日志
- `cboot.web.ErrorHandler`：5xx 记 `error`，4xx 记 `debug`；
  只记录 method/path/status/code，不记录 body/token
- 认证继续使用事件；业务审计用 `[[=EventListener{}]]`
- 访问日志：后续独立 `AccessLog` middleware

## 8. 边界

- 同步写，暂不做异步队列
- 不支持配置热重载
- 不支持插件式 Appender / 自定义 layout 注册
- 不提供 syslog、Kafka、JDBC 等 sink
- 需要 Log4j2 级异步/生态时，后续接 spdlog/quill 后端
