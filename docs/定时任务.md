# 定时任务

定时任务是契约组件 `cboot.schedule`：支持固定延迟和 cron 表达式。
组件不贡献 bean，只贡献一个调度 hook；应用显式选择后，`[[=Scheduled{...}]]`
方法才会被扫描和调度。

---

## 1. 启用组件

```cpp
import cboot.app;
import cboot.schedule;

struct App : application<App> {
    using components = type_list<schedule_component>;
};
```

CMake 消费：

```cmake
find_package(cboot REQUIRED)
find_package(cboot.schedule REQUIRED)

target_link_libraries(app PRIVATE
    cboot::app
    cboot::schedule)
```

`import cboot.schedule;` 提供 `Scheduled` 注解和 `schedule_component`。
未选择组件时，`[[=Scheduled{...}]]` 不会生效，也不会启动调度线程。

---

## 2. 实现原理：组件 hook

### 2.1 为什么调度器不是普通 bean

调度器需要扫描整个 bean 清单的 `Scheduled` 方法，并在全部 bean 构造完成后启动。
普通 bean 做不到：

- 看不到容器里的其他 bean
- `PostConstruct` 可能早于后面 bean 的构造
- 不适合持有跨 bean 的调度线程

所以定时任务用 **组件 hook**：组件不贡献 bean，只在 context 构造完成后安装一个
RAII 挂载点。

### 2.2 hook 契约

组件描述符：

```cpp
export struct schedule_component {
    static constexpr bean_name name{"schedule"};
    using beans = type_list<>;
    using dependencies = type_list<>;
    using hooks = type_list<schedule_hook>;
};
```

Hook 类型提供嵌套实例：

```cpp
struct my_hook {
    template <class Ctx>
    struct instance {
        explicit instance(Ctx& ctx);   // 安装/启动
        ~instance();                   // 停止/清理
        instance(const instance&) = delete;
    };
};
```

安装顺序：

1. `boot_runner` 构造 `context<Ts...> ctx`（全部 bean 构造 + PostConstruct）
2. 构造 `hook_scope<context<Ts...>, Hooks...> hooks(ctx)`
3. hook 实例按组件闭包顺序构造
4. 服务退出/作用域结束：hook 先于 context 析构
5. hook 停止后，context 才执行 PreDestroy

Hook 不是 bean：不参与 DI、不参与 Profile 过滤；需要时自己通过
`ctx.is_active<I>()` 过滤，通过 `ctx.get_at<I>()` 访问 bean。

### 2.3 自定义 hook 示例

```cpp
struct audit_hook {
    template <class Ctx>
    struct instance {
        explicit instance(Ctx& ctx) : ctx_(ctx) {
            // 全部 bean 已构造完成
        }
        ~instance() {
            // 停止后台线程 / 刷新缓冲
        }
    private:
        Ctx& ctx_;
    };
};

export struct audit_component {
    static constexpr bean_name name{"audit"};
    using beans = type_list<>;
    using dependencies = type_list<>;
    using hooks = type_list<audit_hook>;
};
```

应用选择：

```cpp
struct App : application<App> {
    using components = type_list<audit_component>;
};
```

### 2.4 直接使用 hook_scope

不经过 `application`、只用 `context` 时（测试常用）：

```cpp
context<A, B> ctx;
hook_scope<decltype(ctx), audit_hook> hooks(ctx);
```

`hook_scope` 从 `cboot.core.context` 导出，`cboot.app` 也 re-export。
`hooks` 析构时停止 hook，早于 `ctx` 析构。

### 2.5 schedule_hook 做什么

`schedule_hook::instance<Ctx>`：

- 编译期扫描 `Ctx::bean_type<I>` 的 `[[=Scheduled{...}]]` 方法
- 校验 public / 非静态 / 无参数 / 参数二选一 / cron 合法
- 运行时只收集 active bean 的任务
- 每个任务通过 `ctx.get_at<I>()` 调用原方法
- 单 `std::jthread` + condition_variable 等待最近 deadline
- 固定延迟用 steady_clock；cron 用本地时间计算下一次
- 析构 `request_stop` + `join`，先于 context PreDestroy

同一 hook 类型由 `app_hooks_t` 去重；`hook_scope` 按顺序构造。

## 3. 固定延迟

```cpp
class [[=Bean{}]] Cleaner {
public:
    [[=Scheduled{5000}]] void purge() {
        // 上一次执行完成后等 5s
    }

    [[=Scheduled{.fixed_delay_ms = 60000}]] void compact() {
        // 60s
    }
};
```

| 参数 | 类型 | 含义 |
|---|---|---|
| `fixed_delay_ms` | 整数，毫秒 | 上一次执行**完成后**等待多久再执行下一次 |

- `1000` = 1 秒
- 首次执行在 delay 之后，不是启动时立刻执行
- 必须 > 0

## 4. cron 表达式

```cpp
[[=Scheduled{.expression = "* * * * * *"}]]     // 6 段：每秒
[[=Scheduled{.expression = "*/5 * * * *"}]]     // 5 段：每 5 分钟
[[=Scheduled{.expression = "0 0 12 * * 1-5"}]]  // 工作日 12:00
```

### 4.1 字段

| 段数 | 字段 |
|---|---|
| 5 段 | 分 时 日 月 周 |
| 6 段 | 秒 分 时 日 月 周 |

| 字段 | 范围 |
|---|---|
| 秒 | 0-59 |
| 分 | 0-59 |
| 时 | 0-23 |
| 日 | 1-31 |
| 月 | 1-12 |
| 周 | 0-7（0/7 = 周日，1-6 = 周一至周六） |

### 4.2 语法

- `*` / `?`：通配
- `5`：单个值
- `1-5`：范围
- `1,3,5`：列表
- `*/10`：步长
- `1-30/5`：范围内步长
- `10/5`：从 10 到上界，步长 5

### 4.3 语义

- 按本地时区计算
- 日字段与周字段同时受限时按 **OR** 匹配；否则按 **AND**
- 任务执行完后从当前时间计算下一次；错过的触发点不补跑
- 表达式在编译期解析；非法表达式 → 编译错
- 支持 5 段和 6 段；5 段按分钟调度，秒固定为 0

示例：

```text
* * * * * *        每秒
0 * * * * *        每分钟整点
*/10 * * * * *     每 10 秒
0 0 * * * *        每小时整点
0 0 12 * * 1-5     工作日 12:00
0 0 1 * *          每月 1 日 00:00
```

---

## 5. 规则

- 方法必须 public、非静态、无参数
- 方法所在 bean 必须处于活动 Profile
- 任务异常写 stderr，调度器继续运行
- hook 析构 / 服务停止 → 调度线程 `request_stop` + `join`
- 未选择 `schedule_component` → 不扫描、不调度

调度 hook 在 `context` 全部 bean 构造完成后安装，先于 context 析构停止。
同一个调度线程串行执行，不会重入；一个长任务会推迟其他任务。

---

## 6. 诊断

| 场景 | 诊断 |
|---|---|
| 方法带参数 | `cboot: scheduled 'X.y' must take no parameters` |
| 方法非 public | `cboot: scheduled 'X.y' must be public` |
| 静态方法 | `cboot: scheduled 'X.y' must be a non-static member function` |
| 两个参数都设置 | `cboot: scheduled 'X.y' requires exactly one of fixed_delay_ms or expression` |
| 两个参数都为空 | 同上 |
| 非法 cron | `cboot: invalid cron expression '...': ...` |

`fixed_delay_ms` 与 `expression` 必须二选一。

---

## 7. 限制

- 单调度线程，无任务线程池
- 不支持时区配置，按本地时区
- 不支持 cron 月份/星期英文名
- `expression` 使用 `bean_name`（最长 63 字符）
- 任务执行完后计算下一次，不补跑错过的触发点
- 未选择组件时注解不生效
