# 认证（登录态）

`cboot.auth` 是可选契约组件族，提供：

- opaque token 登录态
- `AuthService`：login / logout / kickout
- 全局 `AuthGuard` + 路由策略
- 认证/授权事件
- 路由鉴权注解 `RequireRole` / `RequireScope`
- Header / Cookie 两种 token 传输
- 滑动续期（`active_timeout_s`）

TokenStore 有两种可选项：

| 组件 | Store | 适用 |
|---|---|---|
| `auth_memory_component` | `MemoryTokenStore` | 开发 / 单实例 |
| `auth_postgres_component` | `PgTokenStore` | 多实例 / 重启保持登录态 |

用户存储和密码校验由应用负责；`cboot.auth` 不接触密码。
JWT 校验是独立组件，见 [JWT](JWT.md)。

## 1. 应用装配

```cpp
import cboot.app;
import cboot.auth;

struct App : application<App> {
    using components = type_list<auth_memory_component>;
};
```

单实例/开发用内存 store；多实例用 PostgreSQL store：

```cpp
using components = type_list<auth_postgres_component>;
```

```cmake
find_package(cboot.auth REQUIRED)
find_package(cboot.auth.postgres REQUIRED)  # PG store 时

target_link_libraries(app PRIVATE
    cboot::app
    cboot::auth
    cboot::auth_postgres)
```

`auth_component` 只是核心组件，不提供 TokenStore；不要单独选择。
应用选择 `auth_memory_component` 或 `auth_postgres_component` 二选一。
auth 不依赖 JWT/OpenSSL。

## 2. 配置

```json
{
  "auth": {
    "timeout_s": 7200,
    "active_timeout_s": 1800,
    "token_header": "Authorization",
    "token_prefix": "Bearer ",
    "token_cookie": "cboot_token",
    "cookie_path": "/",
    "cookie_same_site": "Lax",
    "cookie_secure": false,
    "cookie_http_only": true,
    "default_policy": "protected",
    "public_paths": [
      "POST:/api/auth/login",
      "GET:/health",
      "OPTIONS:/**"
    ],
    "protected_paths": [
      "/api/**"
    ]
  }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `timeout_s` | 7200 | 登录态绝对有效期（从登录时刻起） |
| `active_timeout_s` | 0 | 滑动续期窗口；0 关闭。每次请求延长到 `now + active_timeout_s`，不超过绝对有效期 |
| `token_header` | `Authorization` | token 所在 header |
| `token_prefix` | `Bearer ` | 前缀；空字符串表示 header 值就是 token |
| `token_cookie` | 空 | Cookie 名；非空时 header 缺失回退到该 Cookie |
| `cookie_path` | `/` | Set-Cookie 的 Path |
| `cookie_same_site` | `Lax` | Set-Cookie 的 SameSite |
| `cookie_secure` | `false` | 是否加 Secure（HTTPS 部署开启） |
| `cookie_http_only` | `true` | 是否加 HttpOnly |
| `default_policy` | `protected` | 未命中策略时的行为：`protected` / `public` |
| `public_paths` | 空 | 放行表达式 |
| `protected_paths` | 空 | 要求登录表达式 |

### 匹配表达式

```text
POST:/api/auth/login   方法 + 精确路径
GET:/api/users/*       一个路径段
/api/**                任意方法 + 剩余路径
*:/health              任意方法 + 精确路径
```

- 可选 `METHOD:` 前缀
- `*` 匹配一个 segment
- `**` 匹配剩余所有 segment
- 按**注册路由 pattern** 匹配，例如 `/api/users/{id}`
- 404 不触发认证
- `OPTIONS` 自动放行

## 3. 登录

应用校验用户和密码后创建 session：

```cpp
class [[=Bean{}]] LoginApi {
public:
    LoginApi(UserRepository& users, auth::AuthService& sessions)
        : users_(users), sessions_(sessions) {}

    [[=Post{"/api/auth/login"}]]
    Response login(const LoginDto& in) {
        auto user = users_.find(in.name);
        if (!user || !verify_password(in.password, user->password_hash))
            return unauthorized();

        const std::string token = sessions_.login(auth::session{
            .subject = user->id,
            .roles = user->roles,
        });
        Response r = json_response(LoginResult{.token = token});
        sessions_.attach_cookie(r, token);   // token_cookie 为空时无操作
        return r;
    }

private:
    UserRepository& users_;
    auth::AuthService& sessions_;
};
```

密码哈希、登录限流、用户锁定由应用负责。

### Cookie 传输

`token_cookie` 非空时，`AuthGuard` / `AuthService::current` 在
`Authorization` header 缺失时读取同名 Cookie：

```http
Cookie: cboot_token=...
```

- header 与 Cookie 同时存在时 header 优先；header 格式错误不回退 Cookie
- `attach_cookie` 写入 `Set-Cookie`，`clear_cookie` 写入删除 Cookie
- 默认 `HttpOnly` + `SameSite=Lax`；HTTPS 部署设置 `cookie_secure: true`
- 使用 Cookie 传输时，写操作需额外 CSRF 防护（SameSite 之外再加 token）

### 滑动续期

`active_timeout_s > 0` 时，每次通过认证的请求都会把登录态延长到
`now + active_timeout_s`：

```text
issued_at ────────────── timeout_s ──────────────▶ 绝对上限（不可越过）
    └── active_timeout_s ──▶ 当前过期时间，每次请求右移
```

- 绝对上限是 `issued_at + timeout_s`，滑动不能突破
- `active_timeout_s` 为 0 时保持固定过期（默认）
- `MemoryTokenStore` / `PgTokenStore` 已实现持久化续期
- 自定义 `TokenStore` 需覆盖 `touch(token, expires_at)`，默认实现返回
  false（仅本次请求读到新值，不落库）

## 4. AuthGuard

`AuthGuard` 是全局 middleware，按配置决定是否认证：

```text
无路由（404）        → 放行
OPTIONS             → 放行
public_paths 命中          → 放行
protected_paths 或 default_policy → 查询 token
```

成功后：

```cpp
[[=Get{"/api/me"}]]
Response me(const web::request_context& ctx) {
    // AuthGuard 已保证受保护路由有会话；缺失会由 ErrorHandler 转 500
    const auto& s = ctx.get<auth::session>();
    return json_response(s);
}
```

失败时 `AuthGuard` 发布 `authentication_failed` / `authorization_failed`
事件，并抛出结构化 `web::error`，由全局 `ErrorHandler` 生成响应（默认）：

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
```

```json
{"error":"unauthorized"}
```

需要自定义 body / 错误码时注册 `web::ErrorMapper`，不要在每个 handler
里判断登录，见 [全局错误处理](错误处理.md)。

## 5. 角色与 scope

路由注解在 auth 模块中：

```cpp
[[=Get{"/admin"}]]
[[=auth::RequireRole{"admin"}]]
Response admin(const web::request_context& ctx) {
    return json_response(json::value("admin"));
}
```

```cpp
[[=Post{"/orders"}]]
[[=auth::RequireScope{"orders:write"}]]
Response create_order(const web::request_context& ctx) {
    // ...
}
```

控制器级批量标注：

```cpp
struct [[=Bean{}]] [[=auth::RequireRole{"admin"}]] AdminApi {
    [[=Get{"/api/admin/users"}]]
    Response list() { ... }

    [[=Post{"/api/admin/users"}]]
    [[=auth::RequireScope{"users:write"}]]
    Response create() { ... }
};
```

- 类上的 role/scope 应用于该控制器所有路由
- 方法级要求是在类级要求之上追加
- 多个注解是全部满足
- 类级要求不能被方法静默取消；需要例外时拆控制器

`auth_policy_hook` 会合并“类级 + 方法级”要求，生成 `bean.method` 策略表。

语义：

- 未登录 → 401
- 已登录但缺少任一 role/scope → 403
- 可重复标注；全部满足才放行
- 没有 role/scope 注解的路由只受 public/protected 策略控制

实现方式：

- `RequireRole` / `RequireScope` 定义在 auth
- `auth_policy_hook` 在 context 构造完成后扫描 Bean 方法
- 生成 `bean.method → roles/scopes` 策略表
- `AuthGuard` 请求期查表，不依赖 web 路由表新增字段

因此 web 不需要知道 auth 注解。

403 响应：

```http
HTTP/1.1 403 Forbidden
```

```json
{"error":"forbidden"}
```

## 6. logout / kickout

```cpp
[[=Post{"/api/auth/logout"}]]
Response logout(const web::request_context& ctx) {
    sessions_.logout(ctx);
    Response r;
    sessions_.clear_cookie(r);   // Cookie 传输时清除浏览器端 token
    return r;
}
```

踢掉某个用户的全部登录态：

```cpp
sessions_.kickout("user-42");
```

## 7. 认证/授权事件

`AuthGuard` 发布：

```cpp
namespace auth {

struct authentication_failed {
    std::string method;
    std::string path;
    std::string reason;
};

struct authentication_succeeded {
    std::string subject;
    std::string method;
    std::string path;
};

struct authorization_failed {
    std::string subject;
    std::string method;
    std::string path;
    std::string reason;
};

}
```

监听：

```cpp
class [[=Bean{}]] AuthAudit {
public:
    [[=EventListener{}]]
    void failed(const auth::authentication_failed& e) {
        log.warn("auth failed {} {}: {}", e.method, e.path, e.reason);
    }

    [[=EventListener{}]]
    void ok(const auth::authentication_succeeded& e) {
        metrics.inc("auth_ok");
    }
};
```

事件同步派发，监听者异常隔离，不改变 401 响应。

## 8. TokenStore

TokenStore 二选一：

- `auth_memory_component`：进程内，重启丢失、不能多实例共享
- `auth_postgres_component`：表 `cboot_auth_sessions`，支持多实例、重启保持

PG store 使用 `postgres_component` 的同一 PostgreSQL 数据库。

自定义 store 实现：

```cpp
class TokenStore {
public:
    virtual std::string create(auth::session s) = 0;
    virtual std::optional<auth::session> get(std::string_view token) const = 0;
    virtual void revoke(std::string_view token) = 0;
    virtual void revoke_subject(std::string_view subject) = 0;
    // 滑动续期；默认返回 false（不续期）
    virtual bool touch(std::string_view token, std::int64_t expires_at);
};
```

`session` 含 `issued_at`、`expires_at` 与 `device`；滑动续期以
`issued_at + timeout_s` 为绝对上限。

PG store 启动时通过 `PostConstruct` 建表、索引，并给旧表补
`issued_at` 列（`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）。

同一应用只保留一个 `TokenStore` 实现，避免 DI 歧义。

## 9. 安全约束

- token 使用平台 CSPRNG 生成
- token 不写日志、不写事件
- 默认固定过期；`active_timeout_s > 0` 启用滑动续期，绝对上限不可突破
- Cookie 传输默认 `HttpOnly` + `SameSite=Lax`；HTTPS 部署开启 `cookie_secure`
- 生产环境使用 TLS 或 HTTPS 反向代理
- 登录失败限流、密码哈希由应用负责
- 认证/授权失败由 `AuthGuard` 抛 `web::error`，统一走
  [全局错误处理](错误处理.md)；事件只做通知
- 跨域配置见 [CORS](CORS.md)
- 自定义流程见 [自定义认证](自定义认证.md)

## 10. 当前范围

已实现：

- opaque token
- MemoryTokenStore / PgTokenStore
- login / logout / kickout
- 路由 `public_paths` / `protected_paths` / `default_policy` 策略
- `RequireRole` / `RequireScope`（401 / 403）
- 认证/授权事件
- `auth::session` 注入
- Header / Cookie token 传输
- 滑动续期

未实现：

- refresh token（独立于登录态的双 token 流程）
- 多账号体系
- SSO / OAuth2
- Redis store（当前用 PostgreSQL）

JWT 不在本组件内，见 [JWT](JWT.md)。
