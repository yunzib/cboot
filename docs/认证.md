# 认证（登录态）

`cboot.auth` 是可选契约组件，提供：

- opaque token 登录态
- 进程内 `MemoryTokenStore`
- `AuthService`：login / logout / kickout
- 全局 `AuthGuard` + 路由策略
- 认证成功/失败事件

用户存储和密码校验由应用负责；`cboot.auth` 不接触密码。
JWT 校验是独立组件，见 [JWT](JWT.md)。

## 1. 应用装配

```cpp
import cboot.app;
import cboot.auth;

struct App : application<App> {
    using components = type_list<auth_component>;
};
```

```cmake
find_package(cboot.auth REQUIRED)
target_link_libraries(app PRIVATE
    cboot::app
    cboot::auth)
```

`auth_component` 不依赖 OpenSSL/JWT。

## 2. 配置

```json
{
  "auth": {
    "timeout_s": 7200,
    "token_header": "Authorization",
    "token_prefix": "Bearer ",
    "default_policy": "protected",
    "public_paths": [
      "POST:/api/auth/login",
      "GET:/health",
      "OPTIONS:/**"
    ],
    "protected_paths": [
      "/api/**"
    ]
  }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `timeout_s` | 7200 | 登录态绝对过期秒数 |
| `token_header` | `Authorization` | token 所在 header |
| `token_prefix` | `Bearer ` | 前缀；空字符串表示 header 值就是 token |
| `default_policy` | `protected` | 未命中策略时的行为：`protected` / `public` |
| `public_paths` | 空 | 放行表达式 |
| `protected_paths` | 空 | 要求登录表达式 |

### 匹配表达式

```text
POST:/api/auth/login   方法 + 精确路径
GET:/api/users/*       一个路径段
/api/**                任意方法 + 剩余路径
*:/health              任意方法 + 精确路径
```

- 可选 `METHOD:` 前缀
- `*` 匹配一个 segment
- `**` 匹配剩余所有 segment
- 按**注册路由 pattern** 匹配，例如 `/api/users/{id}`
- 404 不触发认证
- `OPTIONS` 自动放行

## 3. 登录

应用校验用户和密码后创建 session：

```cpp
class [[=Bean{}]] LoginApi {
public:
    LoginApi(UserRepository& users, auth::AuthService& sessions)
        : users_(users), sessions_(sessions) {}

    [[=Post{"/api/auth/login"}]]
    Response login(const LoginDto& in) {
        auto user = users_.find(in.name);
        if (!user || !verify_password(in.password, user->password_hash))
            return unauthorized();

        const std::string token = sessions_.login(auth::session{
            .subject = user->id,
            .roles = user->roles,
        });
        return json_response(LoginResult{.token = token});
    }

private:
    UserRepository& users_;
    auth::AuthService& sessions_;
};
```

密码哈希、登录限流、用户锁定由应用负责。

## 4. AuthGuard

`AuthGuard` 是全局 middleware，按配置决定是否认证：

```text
无路由（404）        → 放行
OPTIONS             → 放行
public_paths 命中          → 放行
protected_paths 或 default_policy → 查询 token
```

成功后：

```cpp
[[=Get{"/api/me"}]]
Response me(const web::request_context& ctx) {
    const auto* s = ctx.find<auth::session>();
    if (!s) return unauthorized();
    return json_response(*s);
}
```

失败：

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
```

```json
{"error":"unauthorized"}
```

## 5. logout / kickout

```cpp
[[=Post{"/api/auth/logout"}]]
Response logout(const web::request_context& ctx) {
    sessions_.logout(ctx);
    return Response{};
}
```

踢掉某个用户的全部登录态：

```cpp
sessions_.kickout("user-42");
```

## 6. 认证事件

`AuthGuard` 发布：

```cpp
namespace auth {

struct authentication_failed {
    std::string method;
    std::string path;
    std::string reason;
};

struct authentication_succeeded {
    std::string subject;
    std::string method;
    std::string path;
};

}
```

监听：

```cpp
class [[=Bean{}]] AuthAudit {
public:
    [[=EventListener{}]]
    void failed(const auth::authentication_failed& e) {
        log.warn("auth failed {} {}: {}", e.method, e.path, e.reason);
    }

    [[=EventListener{}]]
    void ok(const auth::authentication_succeeded& e) {
        metrics.inc("auth_ok");
    }
};
```

事件同步派发，监听者异常隔离，不改变 401 响应。

## 7. 自定义 TokenStore

默认 `MemoryTokenStore` 是进程内实现。需要 Redis/数据库时实现：

```cpp
class TokenStore {
public:
    virtual std::string create(auth::session s) = 0;
    virtual std::optional<auth::session> get(std::string_view token) const = 0;
    virtual void revoke(std::string_view token) = 0;
    virtual void revoke_subject(std::string_view subject) = 0;
};
```

同一应用只保留一个 `TokenStore` 实现，避免 DI 歧义。

## 8. 安全约束

- token 使用平台 CSPRNG 生成
- token 不写日志、不写事件
- 默认绝对过期；滑动续期后续提供
- 生产环境使用 TLS 或 HTTPS 反向代理
- 登录失败限流、密码哈希由应用负责
- 自定义流程见 [自定义认证](自定义认证.md)

## 9. 当前范围

已实现：

- opaque token
- 内存 store
- login / logout / kickout
- 路由 `public_paths` / `protected_paths` / `default_policy` 策略
- 成功/失败事件
- `auth::session` 注入

未实现：

- Redis / 持久化 store
- 滑动续期 / refresh token
- 多账号体系
- 路由级角色/scope 注解
- SSO / OAuth2
- Cookie token 传输

JWT 不在本组件内，见 [JWT](JWT.md)。
