# 中间件与扩展点

cboot-framework 的运行时扩展固定为四类，按生命周期划分，不按功能增加字段：

| 扩展点 | 生命周期 | 用途 |
|---|---|---|
| `beans` | DI 构造 → 应用存活 | service、repository、verifier、guard |
| `hooks` | context 构造后 → 停机前 | 后台线程、监听器、启动副作用 |
| `middleware` | 每个请求 | 认证、CORS、限流、请求 ID、日志 |
| `aspects` | 每次方法调用 | 重试、计时、业务埋点 |

middleware 是 **Bean 的角色**，不新增组件描述符字段；组件仍然只声明
`beans` / `dependencies` / `hooks`。

## 1. 全局中间件

```cpp
struct [[=Bean{}]] [[=web::Middleware{.order = 0}]] RequestId {
    Response handle(web::request_context& ctx, const web::next_fn& next) {
        Response r = next();
        r.header("X-Request-Id", "generated-id");
        return r;
    }
};
```

`name` 为空表示全局：所有请求都会经过，包括 404/405 和 OPTIONS。

## 2. 路由级中间件

```cpp
struct [[=Bean{}]]
[[=web::Middleware{.name = "tenant", .order = 100}]] TenantGuard {
    Response handle(web::request_context& ctx, const web::next_fn& next) {
        // 校验 X-Tenant 等
        return next();
    }
};
```

路由方法标注：

```cpp
[[=Post{"/orders"}]]
[[=web::UseMiddleware{"tenant"}]]
Response create_order(const web::request_context& ctx) {
    // ...
}
```

- 只有带 `UseMiddleware{"tenant"}` 的路由才会经过 `TenantGuard`
- 未标注的路由不会经过该中间件
- 一个路由可以标注多个 `UseMiddleware`

## 3. 执行顺序

```text
HTTP parser
  → request_context
  → middleware（按 order 升序，order 小的在外层）
  → 路由匹配结果
  → aspects
  → handler
```

- 全局中间件与命中的路由级中间件合并排序
- 同 order 按中间件 name 稳定排序
- Profile 未激活的中间件 bean 不注册

## 4. request_context

中间件通过 `request_context` 读写请求级数据：

```cpp
struct principal { std::string subject; };

Response handle(web::request_context& ctx, const web::next_fn& next) {
    ctx.put(principal{"user-42"});
    return next();
}
```

handler 可以直接声明 `const web::request_context&` 参数：

```cpp
[[=Get{"/me"}]]
Response me(const web::request_context& ctx) {
    if (const auto* p = ctx.find<principal>())
        return json_response(p->subject);
    return unauthorized();
}
```

`request_context` 的生命周期仅限本次请求；不要保存引用到请求外。

## 5. Request headers

```cpp
[[=Get{"/header"}]]
Response header(const Request& req) {
    auto token = req.header("Authorization");
    auto trace = req.header("X-Request-Id");
    // header 名大小写不敏感；值已去掉首尾空白
}
```

`Request::headers` 是原始 header 块视图；`header()` 零分配查找。

## 6. 短路与 CORS

```cpp
Response handle(web::request_context& ctx, const web::next_fn& next) {
    if (ctx.request.method == "OPTIONS") {
        Response r;
        r.status = 204;
        r.header("Access-Control-Allow-Origin", "*");
        r.header("Access-Control-Allow-Headers", "Authorization, Content-Type");
        return r;
    }
    return next();
}
```

不调用 `next()` 即短路，后续中间件和 handler 都不会执行。
`OPTIONS` 已作为独立 HTTP 方法解析；未命中路由时全局中间件仍会执行。

完整 CORS 策略（来源白名单、预检方法/请求头校验、凭证、暴露头）直接使用
可选组件 `cors_component`，见 [CORS](CORS.md)；上面的手写版本只适合
项目自定义规则。

## 7. 与 aspects 的边界

- middleware：请求级，能读 header、在路由/参数绑定之前短路
- aspects：方法调用级，适合重试、计时、业务埋点

```text
middleware(outer)
  → router
    → aspects(inner)
      → handler
```

认证、CORS、限流、请求 ID 用 middleware；不要用 aspect 做这些。

## 8. 约束

- middleware 必须实现 `handle(request_context&, const next_fn&)`
- 必须标注 `[[=web::Middleware{...}]]`；`name` 为空才是全局
- 不用 `using middleware = ...`，不给组件描述符增加字段
- 不做运行期动态插件；中间件在启动期注册
- 路由级中间件必须显式标注 `UseMiddleware`，漏标就是不启用
