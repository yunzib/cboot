# 自定义认证

本文只描述**不依赖内置认证组件**的自定义实现方式。认证中间件、登录校验、
token 存储和失败处理都由应用自己控制；框架只提供 middleware、
`request_context`、`Request` headers 和事件总线。

## 1. 自定义登录校验

登录接口是普通路由，密码校验和用户存储由应用负责：

```cpp
struct UserRecord {
    std::string id;
    std::string password_hash;
};

struct [[=Bean{}]] UserRepository {
    std::optional<UserRecord> find(std::string_view name);
};

class [[=Bean{}]] LoginApi {
public:
    LoginApi(UserRepository& users, TokenService& tokens)
        : users_(users), tokens_(tokens) {}

    [[=Post{"/api/auth/login"}]]
    Response login(const LoginDto& in) {
        auto user = users_.find(in.name);
        if (!user || !verify_password(in.password, user->password_hash))
            return unauthorized();

        const std::string token = tokens_.issue(user->id);
        return json_response(LoginResult{.token = token});
    }

private:
    UserRepository& users_;
    TokenService& tokens_;
};
```

`TokenService` 是应用自己的 bean，可以：

- 生成随机 opaque token 并写入内存/Redis
- 或签发 JWT
- 或调用外部 IdP

框架不规定 token 格式。

## 2. 自定义认证中间件

```cpp
struct [[=Bean{}]]
[[=web::Middleware{.order = 100}]] ApiTokenGuard {
public:
    ApiTokenGuard(TokenService& tokens, event_publisher& bus)
        : tokens_(tokens), bus_(bus) {}

    Response handle(web::request_context& ctx, const web::next_fn& next) {
        auto header = ctx.request.header("Authorization");
        if (!header) {
            fail(ctx, "missing token");
            return unauthorized();
        }

        auto token = bearer(*header);
        auto session = token ? tokens_.lookup(*token) : std::nullopt;
        if (!session) {
            fail(ctx, "invalid token");
            return unauthorized();
        }

        ctx.put(principal{
            .subject = session->subject,
            .roles = session->roles,
        });
        bus_.publish(LoginSucceeded{
            .subject = session->subject,
            .method = std::string(ctx.request.method),
            .path = std::string(ctx.request.path),
        });
        return next();
    }

private:
    void fail(web::request_context& ctx, std::string reason) {
        bus_.publish(LoginFailed{
            .method = std::string(ctx.request.method),
            .path = std::string(ctx.request.path),
            .reason = std::move(reason),
        });
    }

    TokenService& tokens_;
    event_publisher& bus_;
};
```

这是普通 middleware bean，不依赖内置认证组件。

## 3. 事件定义

事件是应用自己的结构体：

```cpp
struct LoginFailed {
    std::string method;
    std::string path;
    std::string reason;
};

struct LoginSucceeded {
    std::string subject;
    std::string method;
    std::string path;
};
```

事件字段约束：

- 不包含 token
- 不包含密码
- 不包含 Authorization 原文
- `reason` 用固定短语，不拼接用户输入

## 4. 事件监听

```cpp
class [[=Bean{}]] AuthAudit {
public:
    [[=EventListener{}]]
    void on_failed(const LoginFailed& e) {
        std::println("auth failed {} {}: {}", e.method, e.path, e.reason);
        metrics_.inc("auth_failed");
    }

    [[=EventListener{}]]
    void on_succeeded(const LoginSucceeded& e) {
        std::println("auth ok {} {} {}", e.subject, e.method, e.path);
        metrics_.inc("auth_ok");
    }

private:
    Metrics& metrics_;
};
```

特点：

- 同步派发
- 多个监听者按稳定顺序执行
- 单个监听者异常不会改变认证结果，由事件总线隔离
- 日志/指标失败不会把 401 变成 500

## 5. 失败处理策略

### 只记录日志

用 `LoginFailed` 事件，不改认证响应。

### 自定义 401 响应

使用内置 `AuthGuard` 时，不要自己写 middleware；注册
`web::ErrorMapper` 即可，见 [全局错误处理](错误处理.md)。

完全自定义认证 middleware 时，可以直接返回 Response：

```cpp
Response unauthorized() {
    json::object body;
    body.emplace_back("error", json::value("unauthorized"));
    Response r = json_response(json::value(std::move(body)));
    r.status = 401;
    r.header("WWW-Authenticate", "Bearer");
    return r;
}
```

也可以抛 `web::error`，复用全局 `ErrorHandler`：

```cpp
web::error_info info;
info.status = 401;
info.code = "login.required";
info.message = "login required";
throw web::error(std::move(info));
```

### 跳转登录页

```cpp
Response redirect_login() {
    Response r;
    r.status = 302;
    r.header("Location", "/login");
    return r;
}
```

### 审计 / 指标

统一通过 `LoginFailed` / `LoginSucceeded` 事件，不在 middleware 里直接写日志。

## 6. 路由范围

自定义 middleware 需要自己决定放行范围：

- 全局中间件：所有请求都经过
- 路由级中间件：`[[=web::UseMiddleware{"api-token"}]]`
- 白名单/路径策略：自己根据 `ctx.route->pattern` 或配置实现
- 404：`ctx.route == nullptr`，通常直接放行
- OPTIONS：CORS preflight，通常直接放行

不要依赖“默认安全”；认证范围必须显式覆盖所有受保护路由。

## 7. 与请求上下文

认证成功后：

```cpp
ctx.put(principal{...});
```

handler：

```cpp
[[=Get{"/me"}]]
Response me(const web::request_context& ctx) {
    const auto* p = ctx.find<principal>();
    if (!p) return unauthorized();
    return json_response(*p);
}
```

`request_context` 只在本次请求有效，不能保存到请求外。

## 8. 测试建议

自定义认证至少覆盖：

- 无 token → 401
- 非法 token → 401
- 过期 token → 401
- 合法 token → handler 收到 principal
- 失败事件至少被一个 listener 收到
- token 不出现在日志/事件字段中
- OPTIONS / 404 不被误拦截

## 9. 安全约束

- token 比较使用恒定时间比较
- 不把 token/Authorization 写入事件或日志
- 密码哈希由应用选择 Argon2/bcrypt 等
- 生产环境使用 TLS 或 HTTPS 反向代理
- 登录失败限流属于应用层
- 自定义 token 存储需要处理并发和过期清理
