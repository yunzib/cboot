# cboot 使用手册

适用版本：v0.1.0  
工具链：GCC 16.2+（`-freflection`）、CMake 4.3+、Ninja

---

## 1. 概览

cboot 把应用装配放在编译期：

- 依赖图：构造器参数即依赖，编译期做拓扑排序
- 路由表：方法注解在编译期展开，运行时只做路径匹配与派发
- 配置绑定：JSON → 结构体，字段名即键
- 生命周期：构造 → `PostConstruct` → 服务 → 逆序 `PreDestroy`

运行时只保留 HTTP I/O、JSON 序列化和业务代码。没有运行期扫描、代理或反射查表。

主要能力：

| 能力 | 说明 |
|---|---|
| DI | 构造器注入、单例、同基类多实例（`[[=Named{}]]`）、标量配置（`[[=Value{}]]`）、Profile 条件装配、编译期诊断 |
| REST | Get/Post/Put/Delete/Patch、路径参数、JSON body、405/413 |
| 配置 | JSON 文件、前缀绑定、`${ENV:default}` |
| JSON | 值模型 + 解析/序列化 + 反射绑定，流式写入 |
| AOP | 编译期切面链，零代理 |
| 事件 | `[[=EventListener{}]]` + `ctx.publish`，同步派发、异常隔离 |
| 定时 | `[[=Scheduled{ms}]]`，固定延迟、单调度线程、停机取消 |
| 运维 | 内建 `/health`（200/503）、`/beans`（仅 dev） |
| 协程 | `task<T>`、`sync_wait`、事件唤醒 |
| 传输 | threads / IOCP / epoll，keep-alive、pipelining、背压、超时 |
| 打包 | `find_package(cboot)` |
| 许可 | MIT，见 [LICENSE](../LICENSE) |

只导入需要的子模块也可以，但应用代码通常只需 `cboot.app`。

## 3. 第一个应用

```cpp
import cboot.app;
import std;

struct UserDto { std::string name; int age{}; };

class [[=Bean{"repo"}]] UserRepo {
public:
    UserRepo() = default;
    UserDto find(int id) {
        return {.name = "user" + std::to_string(id), .age = 20 + id};
    }
};

class [[=Bean{}]] UserApi {
public:
    UserApi(UserRepo& repo) : repo_(repo) {}

    [[=Get{"/users/{id}"}]]
    Response get(int id) { return json_response(repo_.find(id)); }

    [[=Post{"/users"}]]
    Response create(const UserDto& in) { return json_response(in); }

private:
    UserRepo& repo_;
};

class App : public application<App> {
public:
    App() = default;
    static constexpr unsigned short default_port = 8080;
};

int main() { return App{}.run(); }
```

运行：

```bash
curl http://127.0.0.1:8080/users/42
curl -X POST -d '{"name":"bob","age":30}' http://127.0.0.1:8080/users
```

`App` 同时是自动发现的扫描锚点：当前翻译单元可见、标注 `[[=Bean{}]]` /
`[[=Config{...}]]` 的完整类型会自动进入容器。

## 4. 项目结构

```
packages/  同级包（meta/json/config/core/aop/async/web/app）
           每包自带接口单元与 src/；测试可放包内 test/
cmake/     包构建 helper（cboot_package / cboot_component）
test/      当前跨包冒烟与负面编译用例
examples/  使用示例（standalone/ 为 find_package 独立应用）
docs/      文档
```

接口与实现分离：`packages/<pkg>/*.cppm` 放声明/模板，`packages/<pkg>/src/*.cpp` 放实现。
包在目录和构建图上平级；依赖由 `target_link_libraries` 表达，不用目录嵌套。
新增功能时沿 `app → web.server → routing/http → core/json/aop → meta` 的依赖方向。

## 5. Bean 与依赖注入

### 5.1 注册

唯一类级注解是 `[[=Bean{}]]`：

```cpp
struct [[=Bean{}]] UserService { ... };
class  [[=Bean{"repo"}]] UserRepository { public: ... };
```

- 花括号不可省；裸 `[[=Bean]]` 会被静默忽略
- 注解写在 class-key 之后
- 名字可选，当前用于诊断；注入仍按类型，没有名字限定符
- 每个类型一个实例（单例）
- 控制器没有独立注解，必须显式 `[[=Bean{}]]`

### 5.2 构造器注入

```cpp
struct [[=Bean{}]] UserService {
    UserService(UserRepository& repo, DbProps& cfg)
        : repo_(repo), cfg_(cfg) {}
    UserRepository& repo_;
    DbProps& cfg_;
};
```

构造器选择顺序：

1. 恰有一个 `[[=Inject{}]]` 构造器 → 用它
2. 否则只有一个构造器 → 用它
3. 否则有默认构造器 → 默认构造
4. 多候选且无标注 → 编译错

多构造器示例：

```cpp
struct [[=Bean{}]] Svc {
    [[=Inject{}]] Svc(Repo& repo);   // 指定注入用者
    Svc();                           // 其他候选
};
```

约束：

- 构造器必须 public
- 依赖参数写成 `T&`，按类型（含基类）解析；多实现用 `[[=Named{}]]` 选择（见 5.7）
- 标量参数用 `[[=Value{"key"}]]` 直接取配置（见 5.8），不算 bean 依赖
- 依赖必须是 bean（`[[=Bean{}]]` 或 `[[=Config{...}]]`），或内建依赖
  `const config::properties&` / `event_publisher&`
- 环依赖、缺失依赖、歧义、私有构造器都是编译期错误，并带类型名

### 5.3 配置 bean

任意结构体可声明为配置 bean：

```cpp
struct [[=Config{"db"}]] DbProps {
    std::string host{"localhost"};
    int port{5432};
    int pool_size{8};
};
```

```cpp
struct [[=Bean{}]] UserService {
    UserService(DbProps& db) : db_(db) {}
    DbProps& db_;
};
```

配置 bean 不调用构造器，由 `config::bind<T>(props, "db")` 生成；需要应用提供
配置文件（`application::config_path` 或 `.config(path)`），否则启动时抛
`cboot: config bean requires config`。

需要原始配置时注入 `const config::properties&`：

```cpp
struct [[=Bean{}]] RawConfigReader {
    RawConfigReader(const config::properties& props) : props_(props) {}
    const config::properties& props_;
};
```

没有配置文件时会抛 `cboot: config not provided`。

### 5.4 生命周期

```cpp
struct [[=Bean{}]] Repo {
    [[=PostConstruct{}]] void open();     // 构造后、依赖者构造前
    [[=PreDestroy{}]]  void close();      // 逆拓扑序
};
```

- 生命周期方法必须 public
- 先构造全部 bean，再按拓扑序调用 `PostConstruct`
- 停机时逆序调用 `PreDestroy`
- 生命周期方法不参与 AOP

### 5.5 显式清单（逃生口）

自动发现之外，可以精确指定 bean 集合：

```cpp
int main() {
    return run<UserRepository, UserService, UserApi>(8080);
}
```

或只用容器做测试：

```cpp
context<UserRepository, UserService> ctx;
auto& svc = ctx.get<UserService>();
```

显式清单不走配置文件；如果清单里有配置 bean，启动会报错。

### 5.6 `struct` 与 `class`

两者都支持：

- `class` 的构造器、路由 handler、生命周期方法必须 public
- 私有数据成员允许；框架的 DI 只访问构造器
- 继承 `application` 时必须写 `public` 继承
- DTO 必须是聚合体（成员全 public、无用户构造器），否则 JSON 绑定编译错

### 5.7 同基类多实例（`[[=Named{}]]`）

接口的多个实现可以同时注册，用 bean 名区分：

```cpp
struct DataSource {
    virtual ~DataSource() = default;
    virtual int id() const = 0;
};

struct [[=Bean{"primary"}]] Primary : DataSource {
    int id() const override { return 1; }
};
struct [[=Bean{"replica"}]] Replica : DataSource {
    int id() const override { return 2; }
};
struct [[=Bean{}]] DefaultSource : DataSource {
    int id() const override { return 0; }
};

struct [[=Bean{}]] Service {
    Service([[=Named{"primary"}]] DataSource& p,
            [[=Named{"replica"}]] DataSource& r)
        : primary(p), replica(r) {}
    DataSource& primary;
    DataSource& replica;
};
```

规则：

- 依赖类型可以是基类，候选包括同类型与派生类型
- 带 `Named`：名字必须匹配且只命中一个；缺失/重名 → 编译错
- 不带 `Named`：候选唯一 → 用它；多候选时选唯一的默认实例（无名 `[[=Bean{}]]`）；
  否则编译错并列出候选
- 运行时取用：`ctx.get<DataSource>("primary")`、`ctx.get<DataSource>()`（默认）、
  `ctx.get_at<I>()`（按清单下标）

### 5.8 标量配置注入（`[[=Value{}]]`）

不写配置结构体，直接把配置键注入构造器标量参数：

```cpp
enum class Mode { Fast, Slow };

struct [[=Bean{}]] Pool {
    Pool([[=Value{"db.host"}]] std::string host,
         [[=Value{"db.pool_size"}]] int size,
         [[=Value{"db.timeout"}]] double timeout,
         [[=Value{"db.debug"}]] bool debug,
         [[=Value{"db.mode"}]] Mode mode)
        : host_(std::move(host)), size_(size),
          timeout_(timeout), debug_(debug), mode_(mode) {}
    // ...
};
```

支持类型：`bool`、整数、浮点、`std::string`、枚举；参数按值或 `const&` 声明。
`${ENV:def}` 在读取时展开。

- 缺配置、缺键、值无法转换、枚举名不存在 → 启动期抛 `std::runtime_error`，
  错误带键名与 bean 名
- 非标量类型、空 key、与 `[[=Named{}]]` 同时使用 → 编译错
- Value 参数不参与依赖图，也不要求配置 bean 类型

### 5.9 Profile 条件装配（`[[=Profile{}]]`）

同一份代码在不同环境装配不同 bean：

```cpp
class [[=Profile{"dev"}]] DevSeeder {
public:
    // 仅 dev 激活
};

class [[=Profile{"prod"}]] ProdSeeder {
public:
    // 仅 prod 激活
};

class [[=Bean{}]] AlwaysOn {
public:
    // 没有 Profile 注解：始终激活
};
```

配置激活列表：

```json
{
  "cboot": { "profiles": { "active": "dev,local" } }
}
```

展平后的键是 `cboot.profiles.active`，逗号分隔，忽略空白。

规则：

- 无 `Profile` 注解 → 始终激活
- 有注解 → 名字必须在激活列表中（区分大小写）
- 未激活 bean 不构造、不挂载路由、不可 `get` / `get_at`
- 激活 bean 依赖未激活 bean → 启动期明确报错，并列出当前激活列表
- 没有配置文件（`context(nullptr)` / 显式清单）→ Profile bean 全不激活；
  其中未标注 Profile 的配置 bean 仍会因缺少配置而报错

### 5.10 Profile、Config、Value 的分工

| 注解 | 位置 | 作用 | 不满足时 |
|---|---|---|---|
| `[[=Config{"prefix"}]]` | 类型 | 把 `prefix.*` JSON 子树绑定成 bean | 缺配置/缺键：启动报错或保持默认 |
| `[[=Value{"key"}]]` | 构造器参数 | 把单个配置键转成标量 | 缺键/非法值：启动报错 |
| `[[=Profile{"name"}]]` | 类型 | 决定 bean 是否参与装配 | bean 不构造、不挂载、不可注入 |

启动顺序：

```
application::run()
  1. 加载 JSON → config::properties
  2. context 读取 cboot.profiles.active，标记 active beans
  3. 按拓扑序构造 active beans
     - Config bean → config::bind<T>(props, prefix)
     - Value 参数  → props.get_expanded(key)
  4. PostConstruct
  5. 注册 active bean 的定时任务，启动调度线程（若有）
  6. 只挂载 active beans 的路由
  7. server.run()
```

要点：

- Profile 过滤先于 Config/Value 读取：未激活 bean 不会绑定配置，也不会读 Value
- Profile 不影响编译期依赖图；active bean 依赖 inactive bean 在启动期报错
- Config bean 可以同时标 Profile，但未激活时所有依赖它的 active bean 都会启动失败；
  共享配置 bean 通常不标 Profile
- 一个类型只能标一个 Profile；需要多环境共用时用无注解默认 bean，或拆成多个类型
- Config 管“值是多少”，Value 管“单个标量值”，Profile 管“这个 bean 在不在”

```cpp
class [[=Config{"db"}]] DbProps {
public:
    std::string host{"localhost"};
    int port{5432};
};

class [[=Profile{"dev"}]] DevSeeder {
public:
    DevSeeder(DbProps& db, [[=Value{"app.page_size"}]] int page)
        : db_(db), page_(page) {}
private:
    DbProps& db_;
    int page_;
};
```

`active=dev` 时 `DevSeeder` 构造并读取 `db.*` 与 `app.page_size`；
`active=prod` 时它不构造，也不读这些键。`DbProps` 未标 Profile，两种环境共用。

## 6. 路由与 HTTP

### 6.1 声明路由

```cpp
struct [[=Bean{}]] UserApi {
    [[=Get{"/users"}]]              Response list();
    [[=Get{"/users/{id}"}]]         Response get(int id);
    [[=Post{"/users"}]]             Response create(const UserDto& in);
    [[=Put{"/users/{id}"}]]         Response replace(int id, const UserDto& in);
    [[=Delete{"/users/{id}"}]]      Response remove(int id);
    [[=Patch{"/users/{id}"}]]       Response patch(int id, const UserDto& in);
};
```

路径模板 `{name}` 为参数段；方法不匹配但路径匹配 → `405` + `Allow`；
路径不存在 → `404`。

### 6.2 handler 参数

按声明顺序解释：

| 参数 | 来源 |
|---|---|
| `Request` | 请求本体 |
| 聚合体（`struct` 或全 public `class`） | JSON body |
| 数值 / 字符串 | 路径参数（按 `{x}` 出现序） |

示例：

```cpp
[[=Put{"/users/{id}"}]]
Response replace(int id, const UserDto& in);
```

`id` 取路径，`in` 取 body。返回 `Response`，或 `task<Response>`。

### 6.3 Request / Response

```cpp
struct Request {
    std::string_view method;
    std::string_view path;     // 已解码
    std::string_view query;    // 原始 query
    std::string_view body;

    std::optional<std::string_view> query_raw(std::string_view name) const;
    std::optional<std::string> query_get(std::string_view name) const;
};
```

`Request` 的字段是指向解析器缓冲的视图，只在本次 handler 调用内有效，不要保存。

```cpp
struct Response {
    int status = 200;
    std::string_view content_type = "application/json";
    std::vector<std::pair<std::string, std::string>> headers;
    json::small_buffer<64> body;

    static Response text(std::string s);
    Response& header(std::string name, std::string value);
};
```

- `Response::text(s)`：`text/plain; charset=utf-8`
- `json_response(dto)`：反射流式序列化，默认 `application/json`
- `header()` 可链式追加响应头
- `body` 内联 64 字节，超出自动溢出到堆；可当 `std::string_view` 读

### 6.4 协议行为

| 行为 | 规则 |
|---|---|
| keep-alive | HTTP/1.1 默认复用；`Connection: close` 关闭 |
| 单连接请求上限 | 1024，达到后关闭 |
| 空闲超时 | 15s |
| 单请求读入时限 | 30s（slowloris 防护） |
| 头部上限 | 64 KB |
| body 上限 | 1 MB（超出 413） |
| 背压 | `max_connections` 超限 → 503 |
| handler 预算 | 超支 → 504（SLA 语义，不抢占执行） |

路径段和 query 值做百分号解码；query 中 `+` 解码为空格。

### 6.5 手工挂载

测试或嵌入式使用：

```cpp
router r;
r.mount(api);                 // 无切面
r.mount(api, RequestLog{});   // 带切面
Response resp = r.dispatch("GET", "/users/42", "");
```

## 7. 配置

### 7.1 指定配置文件

```cpp
struct App : application<App> {
    static constexpr std::string_view config_path = "app.json";
};

int main() {
    return App{}.config("prod.json").port(9000).workers(8).run();
}
```

优先级：

- 端口：`.port(n)` > `server.port` > `default_port` > 8080
- 配置路径：`.config(path)` > `config_path`；都没有则不加载配置
- 工作线程：`.workers(n)` > `server.workers` > 硬件并发数

| 调用 / 静态成员 | 作用 |
|---|---|
| `.port(n)` | 覆盖监听端口；`0` = 使用配置/默认值 |
| `.config(path)` | 覆盖配置文件路径 |
| `.workers(n)` | 覆盖工作线程数；`0` = 配置/硬件并发 |
| `config_path` | 静态默认配置路径（可选） |
| `default_port` | 配置未指定端口时的默认值（可选） |
| `aspects` | 应用级切面 tuple（可选） |

### 7.2 JSON 格式

```json
{
  "server": { "port": 8080, "io": "iocp", "workers": 8 },
  "db": {
    "host": "${DB_HOST:localhost}",
    "port": 5432,
    "pool_size": 16,
    "replicas": ["r1", "r2"]
  }
}
```

绑定规则：

- 嵌套对象展平为 `a.b.c`；数组为 `a.0`、`a.1`，也支持逗号分隔单值
- 成员名匹配键尾段；缺失键保留成员默认值
- `optional` 缺键为 `nullopt`
- 支持枚举（按名）和嵌套聚合体（递归子前缀）
- `${ENV_VAR}` / `${ENV_VAR:default}` 在读取时展开
- 构造器标量参数也可用 `[[=Value{"key"}]]` 直接注入，不必写配置结构体（见 5.8）
- Profile 激活列表：`cboot.profiles.active`（逗号分隔，见 5.9）

### 7.3 server 配置

| 键 | 含义 |
|---|---|
| `server.port` | 监听端口；0 = 系统分配 |
| `server.io` | `threads` / `iocp` / `epoll` |
| `server.workers` | 工作线程数 |
| `server.max_connections` | 连接上限；超限 503；0 = 不限 |
| `server.handler_timeout_ms` | handler 预算；超支 504；0 = 不限 |
| `server.send_timeout_ms` | 慢客户端写超时；默认 30s |

`epoll` 仅 Linux 可用；Windows 上选择会明确报错。

## 8. JSON

### 8.1 值模型

```cpp
auto v = json::parse(R"({"name":"bob","age":30})");
std::string name = v.find("name")->as_string();
int age = v.find("age")->as_int();
std::string out = json::dump(v);
```

也支持反射绑定：

```cpp
UserDto dto{.name = "bob", .age = 30};
json::value v = json::from(dto);
UserDto back = json::get_as<UserDto>(v);
```

### 8.2 流式序列化

热路径用 `json::write_to` 或 `json_response`，不建 value 树：

```cpp
Response r;
json::write_to(r.body, dto);   // 直接追加
// 或
return json_response(dto);
```

支持类型（绑定目标）：bool、整数、浮点、`std::string`、`optional<U>`、
`vector<U>`、枚举（按名）、聚合体（递归成员）。超出范围编译错。

序列化（`write_to` / `json_response`）额外支持 `std::string_view`；
`get_as` 不接受 `string_view`（生命周期不安全），请用 `std::string`。

## 9. AOP

> 切入点、展开过程、状态与并发、边界与更多模式见 [AOP.md](AOP.md)。

切面是普通结构体，提供 `around`：

```cpp
struct RequestLog {
    template <class Next>
    Response around(const call_info& ci, Next&& next) {
        auto t0 = std::chrono::steady_clock::now();
        Response r = next();
        auto us = std::chrono::duration_cast<std::chrono::microseconds>(
            std::chrono::steady_clock::now() - t0).count();
        std::println("[aop] {}.{} -> {} ({} us)", ci.bean, ci.method, r.status, us);
        return r;
    }
};
```

挂载：

```cpp
struct App : application<App> {
    static constexpr auto aspects = std::tuple<RequestLog>{};
};
```

或手工：

```cpp
router r;
r.mount(api, RequestLog{}, Auth{});   // 前者最外层
```

- `call_info.bean / .method` 来自编译期反射
- 不调 `next()` 即短路；可捕获 handler 异常并转换
- 切面对象随 mount 复制进链，共享状态用 `shared_ptr`
- 默认织入路由 handler；事件监听者可用 `ctx.publish(event, wrap)` 接链；
  bean 间直接调用不经切面

## 11. 定时任务

方法加 `[[=Scheduled{1000}]]`，按固定延迟重复执行。

### 11.1 参数

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `fixed_delay_ms` | 整数，毫秒 | 是，必须 > 0 | 上一次执行**完成后**等待多久再执行下一次 |

两种写法等价：

```cpp
[[=Scheduled{1000}]]                    // 位置参数：1000ms
[[=Scheduled{.fixed_delay_ms = 1000}]]  // 指定字段（注意前面的点）
```

- `1000` 表示 1 秒，不是 1000 秒
- 首次执行在 1000ms 之后，不是启动时立刻执行
- 缺省值是 0，会编译报错；必须显式给正数

### 11.2 时间语义

这是 **fixed delay**，不是 fixed rate：

```
t=0      启动
t=1000   第 1 次执行
t=1300   执行结束（耗时 300ms）
t=2300   第 2 次执行（结束后再等 1000ms）
```

- 任务耗时越长，实际间隔 = 耗时 + delay
- 同一个调度线程串行执行，不会重入
- 一个长任务会推迟其他定时任务
- 当前没有 initial delay、cron、任务线程池

### 11.3 示例

```cpp
class [[=Bean{}]] Cleaner {
public:
    [[=Scheduled{5000}]] void purge() {
        // 每 5s 执行一次（执行完成后计时）
    }

    [[=Scheduled{.fixed_delay_ms = 60000}]] void compact() {
        // 每 60s 执行一次
    }
};
```

规则：

- 方法必须 public、非静态、无参数
- 任务异常写 stderr，调度器继续运行
- 容器析构 / 服务停止 → 调度线程 `request_stop` + `join`
- 未激活 Profile 的 bean，其定时任务不注册

调度在 `context` 构造完成后启动；`application<App>` 在全部 bean 装配后启动。

## 12. 健康检查与运维端点

应用启动时自动挂载两个路由，不需要写控制器。

### 12.1 `/health`

```bash
curl -i http://127.0.0.1:8080/health
```

健康时返回 200：

```json
{"status":"UP","beans":5,"startup_ms":3}
```

| 字段 | 含义 |
|---|---|
| `status` | `UP` / `DOWN` |
| `beans` | 当前激活 bean 数量 |
| `startup_ms` | 容器构造耗时（含 bean 构造与 PostConstruct） |
| `reason` | 仅 DOWN 时出现，失败原因 |

标记 DOWN：业务 bean 注入内建 `health_registry&`：

```cpp
class [[=Bean{}]] Db {
public:
    explicit Db(health_registry& health) : health_(health) {}

    void check() {
        if (/* 连接失败 */)
            health_.set_unhealthy("db down");
        else
            health_.set_healthy();
    }

private:
    health_registry& health_;
};
```

- `health_registry` 是容器提供的内建依赖，不是 bean
- 线程安全；可在请求处理、定时任务或后台线程中更新
- DOWN 时 `/health` 返回 **503**，body 带 `reason`

### 12.2 `/beans`

仅当 `cboot.profiles.active` 包含 `dev` 时暴露；否则 404。

```bash
# app.json: { "cboot": { "profiles": { "active": "dev" } } }
curl http://127.0.0.1:8080/beans
```

返回数组：

```json
[
  {
    "type": "UserApi",
    "name": "",
    "profile": "",
    "active": true,
    "deps": ["UserService"]
  }
]
```

| 字段 | 含义 |
|---|---|
| `type` | bean 类型名 |
| `name` | `[[=Bean{"name"}]]` 的名字；空 = 默认实例 |
| `profile` | `[[=Profile{"name"}]]`；空 = 始终激活 |
| `active` | 当前是否激活 |
| `deps` | 构造器依赖类型名；内建依赖不列 |

未激活 bean 也会出现在清单中（`active=false`），因为类型扫描在编译期完成。

## 13. 协程

```cpp
task<Response> profile(int id) {
    auto user = co_await load_user(id);
    co_return json_response(user);
}

[[=Get{"/profile/{id}"}]]
task<Response> profile_handler(int id) { co_return co_await profile(id); }
```

- `task<T>` 惰性启动、对称转移、异常经 promise 传播
- `sync_wait` 只能等待不会挂起在外部事件上的任务；dispatch 用它执行 `task<Response>`
- `awaitable_event` 一次性；`async_event` auto-reset，供 I/O 完成唤醒
- 当前没有自带调度器；不要 co_await 依赖服务器循环喂事件的对象

## 14. 自动发现

`application<App>::run()` 在调用点扫描当前 TU 可见的全局命名空间：

- 收集 `[[=Bean{}]]` 与 `[[=Config{...}]]`
- 其他类型（DTO/工具类）自动排除
- 上限 128 个 bean
- 控制器漏标 `[[=Bean{}]]` → 编译错并指出类型名

可见性边界：只能看到本 TU 直接声明的类型，或 `import` 的模块 `export` 的类型。
模块内声明不加 `export`，导入方扫描不到，会表现为后续依赖缺失。

`run()` 只应在程序入口调用一次；多 TU 同时调用会有 ODR/清单合并风险。

## 18. 常见问题

**注解没生效**

- 检查是否写成 `[[=Bean{}]]`（必须有花括号）
- 检查是否在 class-key 之后：`struct [[=Bean{}]] X`
- 注解值类型必须是 structural；字符串用 `bean_name` / `path_name`

**编译报构造器/成员函数 private**

- 构造器、路由 handler、生命周期方法必须 public
- 私有数据成员可以保留

**运行时 404**

- 控制器类是否标了 `[[=Bean{}]]`
- 类型是否在当前 TU 可见（跨模块要 `export`）
- `run()` 是否只调用了一次
- 是否被 `[[=Profile{...}]]` 过滤掉了：检查 `cboot.profiles.active`

**Profile bean 没生效**

- 名字是否在 `cboot.profiles.active` 里（区分大小写、逗号分隔）
- 是否真的加载了配置文件（`config_path` / `.config(path)`）
- 显式清单 `run<Beans...>` 与 `context(nullptr)` 没有配置，Profile bean 全不激活

**启动报 inactive under profile**

- 某个 active bean 依赖了未激活 bean；激活该 profile，或去掉这条依赖
- 检查被依赖的配置 bean 是否也标了 Profile

**配置 bean 启动报错**

- 是否提供了 `config_path` / `.config(path)`
- 显式清单 `run<Beans...>` 不加载配置文件
- 注意 `Config`（子树绑定）、`Value`（单键标量）、`Profile`（bean 是否装配）
  是三件不同的事，见 5.10

**Windows 上选 epoll 报错**

- epoll 后端仅 Linux；Windows 用 `iocp` 或 `threads`

**`Response::body` 不是 `std::string`**

- 它是 `json::small_buffer<64>`；读用隐式 `std::string_view`，写可直接赋值
  `std::string`，不要取 `&body` 当 `std::string*`

**协程 handler 抛 `sync_wait` 错误**

- handler 的 task 挂起在外部事件上；`sync_wait` 只能等待自行完成的任务

**事件监听者没触发**

- 方法是否标了 `[[=EventListener{}]]`（花括号不可省）
- 参数去掉 cv/引用后是否与 `publish` 的事件类型完全一致（不走基类匹配）
- bean 是否被 Profile 过滤、方法是否 public / 非静态
- 业务 bean 是否注入了 `event_publisher&`，而不是自己创建 publisher
- `publish` 是否在同一个容器实例上调用

**事件监听者异常**

- 默认写 stderr 后继续，其他监听者不受影响
- `set_event_error_handler` 可替换为收集/上报；`event_result.failed` 有计数

**定时任务没执行**

- 方法是否标了 `[[=Scheduled{...}]]`，`fixed_delay_ms > 0`
- 方法是否 public、非静态、无参数
- bean 是否被 Profile 过滤
- 首次执行在 delay 之后；容器已析构时调度线程已停止

**定时任务抛异常**

- 默认写 stderr 后继续调度，不会杀死调度线程
- 任务本身应自行处理可恢复错误；长任务会推迟后续任务

**`/health` 返回 503**

- 某个 bean 注入了 `health_registry&` 并调用了 `set_unhealthy`
- 看返回 JSON 的 `reason`；恢复时调用 `set_healthy()`
- 没有业务标记时默认是 UP/200

**`/beans` 返回 404**

- 仅在 `cboot.profiles.active` 包含 `dev` 时暴露
- 检查配置是否加载、profile 名是否写对

## 19. 注解速查

| 注解 | 位置 | 作用 |
|---|---|---|
| `[[=Bean{}]]` / `[[=Bean{"name"}]]` | 类型 | 注册 bean；名字供 `Named` 选择，也用于诊断 |
| `[[=Config{"prefix"}]]` | 类型 | 配置 bean，按前缀绑定 |
| `[[=Inject{}]]` | 构造器 | 多构造器时指定注入用者 |
| `[[=Named{"name"}]]` | 构造器参数 | 在多个同基类实例中选择 bean |
| `[[=Value{"key"}]]` | 构造器参数 | 直接注入标量配置（bool/数值/string/枚举） |
| `[[=Profile{"name"}]]` | 类型 | 仅当 profile 激活时装配 |
| `[[=EventListener{}]]` | 方法 | 订阅事件；参数类型即事件类型 |
| `[[=Scheduled{ms}]]` | 方法 | 固定延迟定时任务（public/非静态/无参数） |
| `[[=PostConstruct{}]]` | 方法 | 构造后、依赖者构造前调用 |
| `[[=PreDestroy{}]]` | 方法 | 逆拓扑序销毁 |
| `[[=Get{"/path"}]]` | 方法 | GET 路由 |
| `[[=Post{"/path"}]]` | 方法 | POST 路由 |
| `[[=Put{"/path"}]]` | 方法 | PUT 路由 |
| `[[=Delete{"/path"}]]` | 方法 | DELETE 路由 |
| `[[=Patch{"/path"}]]` | 方法 | PATCH 路由 |

### 18.1 参数含义

| 注解 | 参数 | 类型 | 必填 / 默认 | 含义 |
|---|---|---|---|---|
| `Bean` | `name` | 字符串 | 可选，默认空 | bean 名；供 `Named` 选择，也用于诊断；空 = 默认实例 |
| `Config` | `prefix` | 字符串 | 可选，默认空 | JSON 前缀；`db` 表示绑定 `db.*`；空 = 根 |
| `Inject` | — | — | — | 无参数 |
| `Named` | `name` | 字符串 | 必填 | 匹配 `[[=Bean{"name"}]]`；空等价未限定 |
| `Value` | `key` | 字符串 | 必填且非空 | 扁平配置键，如 `db.pool_size`；类型见 5.8 |
| `Profile` | `name` | 字符串 | 必填 | 匹配 `cboot.profiles.active` 中的名字 |
| `EventListener` | — | — | — | 无参数；事件类型取自方法参数 |
| `Scheduled` | `fixed_delay_ms` | 整数（毫秒） | 必填且 > 0 | 执行完成后等待多久；`1000` = 1s；首次在 delay 后 |
| `PostConstruct` | — | — | — | 无参数 |
| `PreDestroy` | — | — | — | 无参数 |
| `Get` / `Post` / `Put` / `Delete` / `Patch` | `path` | 字符串 | 必填 | 路径模板；`{x}` 参数按 handler 参数序消费 |

注意：

- 注解值必须带花括号：`[[=Bean{}]]`，裸 `[[=Bean]]` 会被静默忽略
- 字符串容量：`bean_name` 为 `char[64]`、路由 `path_name` 为 `char[128]`；超长编译错
- `Scheduled` 指定字段时写 `.fixed_delay_ms = 1000`（前面的点不能省）
- `Value` 的键是展平后的键，不是 JSON 指针：`db.pool_size`，不是 `/db/pool_size`
