# ORM 组件（PostgreSQL / MySQL）

> 可选契约组件。通用 ORM 在 `cboot.orm`，具体数据库由驱动组件
> `cboot.orm.postgres` / `cboot.orm.mysql` 提供。
> 用户侧以类型安全 DSL 和实体 CRUD 为主，复杂 SQL 保留原生逃生口。

## 1. 目标

- 以契约组件形式提供 ORM：应用显式选择驱动组件后才装配
- 实体映射基于 C++26 静态反射，不引入运行期反射/RTTI
- 通用层不链接任何数据库客户端；驱动差异收敛到 `orm::dialect`
- 支持 PostgreSQL（libpq）与 MySQL（libmysql）
- 用户侧提供**有界类型安全 DSL**：
  - 实体 CRUD 自动生成 SQL
  - 单表 select / where / order / limit / offset
  - update / delete 类型安全条件
- 复杂查询提供原生 SQL + 自动行映射
- 连接池、健康检查、配置复用现有机制
- 核心包保持零数据库依赖

非目标：

- 完整 SQL DSL（join / CTE / window / 聚合全部 DSL 化）
- 关系映射、懒加载、identity map、级联
- 迁移工具、数据库版本管理
- 复合主键、联合索引、乐观锁
- 异步数据库调用
- 嵌套事务 / savepoint / 隔离级别配置

## 2. 包结构

```text
packages/orm/                   # 通用层：零数据库客户端依赖
├── CMakeLists.txt
├── orm.annotations.cppm        # Table / Column / Id / error
├── orm.driver.cppm             # dialect / DataSource / connection / statement
├── orm.meta.cppm               # 实体元数据 + 方言无关 SQL 生成
├── orm.dsl.cppm                # 类型安全 DSL（条件 AST）
├── orm.cppm                    # EntityManager + orm_component
└── test/orm_smoke.cpp

packages/orm.postgres/          # PostgreSQL 驱动
├── orm.postgres.cppm           # PgProps / PgDialect / PgDataSource
├── src/postgres.cpp            # libpq 实现
└── test/postgres_smoke.cpp

packages/orm.mysql/             # MySQL 驱动
├── orm.mysql.cppm              # MysqlProps / MysqlDialect / MysqlDataSource
├── src/mysql.cpp               # libmysql 实现
└── test/mysql_smoke.cpp
```

模块与 CMake target：

| 包 | 模块 | target | `find_package` |
|---|---|---|---|
| 通用 | `cboot.orm` | `cboot::orm` | `cboot.orm` |
| PostgreSQL | `cboot.orm.postgres` | `cboot::orm_postgres` | `cboot.orm.postgres` |
| MySQL | `cboot.orm.mysql` | `cboot::orm_mysql` | `cboot.orm.mysql` |

驱动模块会 `export import cboot.orm`，因此 `import cboot.orm.postgres`
或 `import cboot.orm.mysql` 即可获得通用 ORM 词汇。

## 3. 组件描述符

通用组件只贡献 `EntityManager`：

```cpp
export struct orm_component {
    static constexpr bean_name name{"orm"};
    using beans = type_list<orm::EntityManager>;
    using dependencies = type_list<>;
};
```

驱动组件贡献配置和 `DataSource`，并依赖通用组件：

```cpp
export struct postgres_component {
    static constexpr bean_name name{"orm.postgres"};
    using beans = type_list<orm::PgProps, orm::PgDataSource>;
    using dependencies = type_list<orm_component>;
};

export struct mysql_component {
    static constexpr bean_name name{"orm.mysql"};
    using beans = type_list<orm::MysqlProps, orm::MysqlDataSource>;
    using dependencies = type_list<orm_component>;
};
```

应用只选择驱动组件：

```cpp
import cboot.app;
import cboot.orm.postgres;       // 或 cboot.orm.mysql

struct App : application<App> {
    using components = type_list<postgres_component>;
};
```

依赖闭包自动带入 `orm_component`，最终 bean：

```text
PgProps        [[=Config{"db"}]]
PgDataSource   PgProps& + health_registry&
EntityManager  DataSource&（实际注入 PgDataSource）
```

MySQL 对应 `MysqlProps` / `MysqlDataSource`。同一应用只选择一个驱动；
两个驱动的配置前缀都是 `db`。

连接池生命周期使用 `[[=PostConstruct{}]]` / `[[=PreDestroy{}]]`，不需要 hook。

## 4. 实体契约

### 4.1 注解

```cpp
export struct Table {
    bean_name name{};
    bean_name schema{};
};

export struct Column {
    bean_name name{};
};

export struct Id {
    bool generated{};
};
```

实体：

```cpp
struct [[=Table{.name = "users", .schema = "public"}]] User {
    [[=Id{.generated = true}]] std::int64_t id{};
    [[=Column{"display_name"}]] std::string name;
    std::optional<std::string> email;
    bool active{};
};
```

规则：

- 实体必须是 aggregate、可默认构造
- 恰好一个 `Id`
- `Table` 可省略：默认使用类型名、当前 schema/database
- `Column` 可省略：默认使用成员名
- `Table::schema`：PostgreSQL 是 schema；MySQL 是 database 限定符
- 表名/列名是编译期常量，不来自用户输入
- 实体本身不是 bean，只是类型

### 4.2 支持类型

| C++ 类型 | 逻辑类型 | PostgreSQL | MySQL |
|---|---|---|---|
| `bool` | `boolean` | `BOOLEAN` | `TINYINT(1)` |
| `std::int32_t` / `int` | `integer` | `INTEGER` | `INT` |
| `std::int64_t` | `big_integer` | `BIGINT` | `BIGINT` |
| `float` / `double` | `real` | `DOUBLE PRECISION` | `DOUBLE` |
| `std::string` | `text` | `TEXT` | `TEXT` |
| 枚举 | `text` | `TEXT` | `TEXT` |
| `std::optional<U>` | 可空列 | 同 U | 同 U |
| 整数 + `Id{generated}` | 自增主键 | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` |

第一版不支持：嵌套实体、集合、关系、复合主键、`std::chrono`、JSON/JSONB。

### 4.3 编译期元数据

```cpp
template <class T>
inline constexpr auto entity_meta_v = ...;

template <class T>
using id_type = ...;

template <class M>
inline constexpr sql_type sql_type_of();
```

实现要点：

- 用 `nth_member<T, I>()` / `nth_member_name<T, I>()` 枚举成员
- 用 `annotation_of<Id>()` / `annotation_of<Column>()` 读成员注解
- 注解值复制到固定 `bean_name`，不把 `string_view` 指向临时 `extract` 结果
- 校验：
  - 无 `Id` / 多个 `Id` → 编译错
  - 重复列名 → 编译错
  - 不支持成员类型 → `static_assert`
  - 自增主键不是整数 → 编译错

## 5. SQL 方言与生成

### 5.1 dialect

```cpp
enum class sql_type { boolean, integer, big_integer, real, text };

class dialect {
public:
    virtual std::string quote_identifier(std::string_view) const = 0;
    virtual std::string placeholder(std::size_t index) const = 0;
    virtual std::string type_name(sql_type) const = 0;
    virtual std::string identity_type(sql_type) const = 0;
    virtual std::string insert_default_values(std::string_view table) const = 0;
    virtual bool supports_returning() const = 0;
    virtual bool supports_ilike() const = 0;
};
```

| 能力 | PostgreSQL | MySQL |
|---|---|---|
| 标识符 | `"name"`，`"` 双写 | `` `name` ``，`` ` `` 双写 |
| 占位符 | `$1..$n` | `?` |
| 自增 | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` |
| 自增回填 | `INSERT ... RETURNING` | `connection::last_insert_id()` |
| `ILIKE` | 原生 | 降级为 `LOWER(col) LIKE LOWER(?)` |

`EntityManager` 每次生成 SQL 时从 `DataSource::dialect()` 取方言；
同一份实体元数据可以运行在不同驱动上。

### 5.2 标识符

- PostgreSQL 表：`"schema"."table"`
- MySQL 表：`` `database`.`table` ``
- 列按方言引用
- 表/列名来自代码/注解，不拼接用户输入

### 5.3 CRUD

PostgreSQL：

```sql
INSERT INTO "public"."users" ("display_name","email","active")
VALUES ($1,$2,$3)
RETURNING "id"
```

MySQL：

```sql
INSERT INTO `users` (`display_name`,`email`,`active`)
VALUES (?,?,?)
```

规则：

- 插入时排除自增主键
- PostgreSQL 用 `RETURNING` 回填自增 id
- MySQL 在 INSERT 后读 `mysql_insert_id` 回填
- 更新/删除返回影响行数
- 所有值通过 `statement::bind` 进入驱动；PostgreSQL 服务端参数化，
  MySQL 在驱动内部转义后替换 `?`

### 5.4 建表（开发/测试）

PostgreSQL：

```sql
CREATE TABLE IF NOT EXISTS "public"."users" (
    "id" BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "display_name" TEXT NOT NULL,
    "email" TEXT,
    "active" BOOLEAN NOT NULL
);
```

MySQL：

```sql
CREATE TABLE IF NOT EXISTS `users` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
    `display_name` TEXT NOT NULL,
    `email` TEXT,
    `active` TINYINT(1) NOT NULL
);
```

生产迁移不放进 ORM；只提供 `create_schema<T>()` / `drop_schema<T>()`。

## 6. 类型安全 DSL

### 6.1 列引用

```cpp
orm::col<^^User::name>()
```

`col<^^T::member>()` 在编译期：

- 校验成员属于实体
- 算出成员下标
- 读取 `Column` 注解或成员名
- 返回 `column_expr<T, V>`

### 6.2 Select

```cpp
auto users = db.select<User>()
    .where(orm::col<^^User::active>() == true
        && orm::col<^^User::age>() > 18)
    .order_by(orm::desc(orm::col<^^User::age>()))
    .limit(20)
    .offset(0)
    .fetch();

auto one = db.select<User>()
    .where(orm::col<^^User::id>() == 42)
    .fetch_one();       // std::optional<User>
```

PostgreSQL 渲染：

```sql
SELECT "id",... FROM "public"."users"
WHERE ("active" = $1) AND ("age" > $2)
ORDER BY "age" DESC
LIMIT 20 OFFSET 0
```

MySQL 渲染相同结构，标识符变反引号、占位符变 `?`。

### 6.3 Where 能力

- `==` `!=` `<` `<=` `>` `>=`
- `&&` `||` `!`
- `is_null(col)` / `is_not_null(col)`
- `in(col, range)`；空集合生成 `FALSE`
- `like(col, pattern)` / `ilike(col, pattern)`

`in` 的每个元素一个参数。比较类型在编译期检查；例如整数列不能和
`std::string` 比较。条件保存为 AST，执行时才按 dialect 渲染。

### 6.4 Update / Delete

```cpp
db.update<User>()
    .set(orm::col<^^User::name>(), "bob")
    .where(orm::col<^^User::id>() == 42)
    .execute();

db.remove<User>()
    .where(orm::col<^^User::id>() == 42)
    .execute();
```

- update 至少一个 `set()`，且必须有 `where()`
- delete 必须有 `where()`，避免误删全表
- 无条件全表操作请使用原生 SQL 显式表达

### 6.5 直接实体 CRUD

```cpp
auto u = db.find<User>(42);       // optional<User>
auto all = db.all<User>();
db.insert(u);                     // 自增 id 回填
db.update(*u);
db.remove<User>(42);
```

## 7. 事务与原生 SQL

### 7.1 事务

```cpp
db.transaction([](orm::session& tx) {
    User u{.name = "alice", .active = true};
    tx.insert(u);

    tx.execute("UPDATE stock SET count = count - 1 WHERE id = "
                   + tx.dialect().placeholder(1), {1});

    // 抛异常 → ROLLBACK
    // 正常返回 → COMMIT
});
```

语义：

- 从连接池借一个连接并固定给 `session`
- 事务内 CRUD / DSL / 原生 SQL 共用同一连接
- 正常返回 → `COMMIT`
- 抛异常 → `ROLLBACK` 后重新抛出
- `session` 析构未完成时自动回滚
- 不支持嵌套事务/savepoint
- `session` 不是线程安全的

事务内访问数据库必须使用传入的 `tx`：

- `tx.insert/update/remove`
- `tx.select/update/remove` DSL
- `tx.query/fetch_rows/execute`

不要在事务回调里调用 `EntityManager` 的 CRUD。`EntityManager` 会再从池里
借一个连接，这些操作不属于当前 `tx`，也不会随 `tx` 一起回滚。

```cpp
User a{.name = "alice", .active = true};
User b{.name = "bob", .active = true};

db.transaction([&](orm::session& tx) {
    tx.insert(a);        // 在事务内
    // db.insert(b);     // 错：另一个连接，独立于当前事务
});
```

#### 异常与失败处理

回调内抛异常会立即回滚，异常继续向外传播：

```cpp
void transfer(orm::EntityManager& db, int amount) {
    try {
        db.transaction([&](orm::session& tx) {
            if (amount < 0)
                throw orm::error("amount must be non-negative");

            tx.execute(
                "UPDATE account SET balance = balance - "
                    + tx.dialect().placeholder(1)
                    + " WHERE id = " + tx.dialect().placeholder(2),
                {std::int64_t(amount), std::int64_t(1)});
        });
    } catch (const std::exception& e) {
        std::println("transaction rolled back: {}", e.what());
        throw;   // 或转成 400/409/500
    }
}
```

要点：

- 回滚发生在 `transaction` 内部；外层 `catch` 时数据已经回滚
- **不要在回调内 `catch` 后正常返回**，否则事务会继续提交
- 如果需要在回调外统一转 HTTP 状态，直接把异常抛到外层

#### 显式取消

需要主动取消时调用 `tx.rollback()`：

```cpp
User pending{.name = "pending", .active = true};
const bool cancelled = pending.name.empty();

db.transaction([&](orm::session& tx) {
    tx.insert(pending);

    if (cancelled) {
        tx.rollback();   // 立即回滚
        return;          // 正常返回，但 transaction 检测 finished() 后不再 COMMIT
    }

    // 后续操作
});
```

`tx.rollback()` 后回调可以正常返回；`transaction` 看到 `session::finished()`
为 true，会跳过 `COMMIT`。

如果回调有返回值，rollback 后仍会把该值返回给调用方，但数据并未提交；
业务上不要把这种返回值当作成功结果。

#### 返回值

```cpp
auto created = db.transaction([](orm::session& tx) {
    User u{.name = "alice", .active = true};
    tx.insert(u);
    return u;
});
```

只有 `transaction` 正常返回后才表示已提交；rollback 分支不应返回
“成功”语义的对象。

### 7.2 原生 SQL

join / 聚合 / CTE / 方言特性走原生 SQL：

```cpp
auto rows = db.query<User>(R"(
    SELECT u.id,
           u.display_name,
           u.email,
           u.active
    FROM users u
    JOIN orders o ON o.user_id = u.id
    WHERE u.active = $1
)", {true});
```

`query<T>` 按**结果列名**映射，允许列顺序不同：

- 列名与实体 `Column` 元数据匹配
- 缺列抛 `orm::error`
- `fetch_rows<T>` 仍按 SELECT 列顺序映射，作为更低层入口
- 参数通过 `db_value` 传入；PostgreSQL 用 `$n`，MySQL 用 `?`
- SQL 字符串由调用方负责；ORM 只做连接、绑定、映射
- MySQL 文本协议会把 SQL 中的每个 `?` 都当作参数占位符，
  原生 SQL 里需要字面量 `?` 时请改用其他写法

事务内同样可用：

```cpp
db.transaction([](orm::session& tx) {
    auto rows = tx.query<User>("SELECT ...", {});
});
```

### 7.3 schema 迁移（版本化）

`create_schema` 只适合开发/测试的一次性建表；线上 schema 演进用
`orm::MigrationRunner`（Flyway 最小子集，前进式）：

```cpp
struct [[=Bean{}]] Migrator {
    explicit Migrator(orm::MigrationRunner& mig) : mig_(mig) {}

    [[=PostConstruct{}]] void init() {
        static const std::array<orm::migration_script, 2> scripts{{
            {1, "create users",
             "CREATE TABLE users ("
             "id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,"
             " display_name TEXT NOT NULL)"},
            {2, "add users.email",
             "ALTER TABLE users ADD COLUMN email TEXT"},
        }};
        mig_.run(std::span<const orm::migration_script>(scripts));
    }

    orm::MigrationRunner& mig_;
};
```

语义：

- 版本表默认 `cboot_schema_version`（version/description/applied_ms），
  不存在时自动建；`run()` 只执行 version 大于当前最大值的脚本
- 脚本与版本行插入**同一事务**提交；失败回滚、抛 `orm::error`
  （消息含版本号与说明），已提交的前序脚本保留
- `version` 必须为正且严格递增（重复/乱序在触库前报错）；
  重复启动幂等（`run()` 返回本次应用数，0 = 已最新）
- 声明顺序无关（按 version 排序执行），但建议按版本号书写
- 日志：每次应用输出 info（logger `cboot.orm.migration`）
- 边界：不做 down/undo、校验和比对；PG 单脚本可多语句，
  MySQL 文本协议一脚本一语句（多语句请拆脚本）
- 迁移是**应用代码里的显式调用**（PostConstruct），不是自动扫描
- 多实例并发：版本行**先**占位（version 列带 UNIQUE）再执行脚本，
  第二个实例插入冲突即回滚失败退出——不会重复执行 DDL；k8s 滚动更新
  建议迁移阶段单副本（Job / initContainer），且脚本本身要可重入
  （MySQL 的 DDL 隐式提交，失败后版本行可能已随隐式提交落库）

## 8. 连接池与配置

### 8.1 PostgreSQL 配置

```cpp
export struct [[=Config{"db"}]] PgProps {
    std::string url{"postgresql://localhost/postgres"};
    std::string user;
    std::string password;
    std::string sslmode{"prefer"};
    int pool_size{4};
    int connect_timeout_s{5};
    int acquire_timeout_ms{5000};
    int idle_probe_s{30};
    int slow_query_ms{200};
};
```

```json
{
  "db": {
    "url": "postgresql://127.0.0.1:5432/app",
    "user": "app",
    "password": "${PGPASSWORD}",
    "sslmode": "prefer",
    "pool_size": 4,
    "connect_timeout_s": 5,
    "acquire_timeout_ms": 5000
  }
}
```

密码规则：

- `password` 留空：libpq 读取 `PGPASSWORD` 环境变量
- `password` 写 `${PGPASSWORD}`：由 config 展开；未展开时回退 libpq
- `password` 直接写值：使用该值（不建议写进仓库）
- `url` 支持 URI 或 keyword=value conninfo；`user` / `password` /
  `sslmode` 等字段覆盖 URL 中的同名项
- 不打印连接串或密码

### 8.2 MySQL 配置

```cpp
export struct [[=Config{"db"}]] MysqlProps {
    std::string host{"127.0.0.1"};
    int port{3306};
    std::string database{"mysql"};
    std::string user{"root"};
    std::string password;
    std::string charset{"utf8mb4"};
    int pool_size{4};
    int connect_timeout_s{5};
    int acquire_timeout_ms{5000};
    int idle_probe_s{30};
    int slow_query_ms{200};
};
```

```json
{
  "db": {
    "host": "127.0.0.1",
    "port": 3306,
    "database": "app",
    "user": "app",
    "password": "${MYSQL_PWD}",
    "charset": "utf8mb4",
    "pool_size": 4,
    "connect_timeout_s": 5,
    "acquire_timeout_ms": 5000
  }
}
```

密码规则：

- `password` 留空：回退 `MYSQL_PWD`
- `password` 写 `${MYSQL_PWD}`：由 config 展开；未展开时回退环境变量
- `password` 直接写值：使用该值（不建议写进仓库）

### 8.3 连接池行为

- `pool_size` 个连接在 `open()`（PostConstruct）中建立
- mutex + condition_variable 管理空闲连接
- 池满时按 `acquire_timeout_ms` 等待；超时抛 `orm::error`
- **借出前活性校验**：本地状态检查（零开销）之外，连接空闲超过
  `idle_probe_s` 秒时做一次真实探测（PostgreSQL 空查询往返 /
  MySQL `mysql_ping`）；失败 → 销毁死连接并重建（池容量不变、
  业务无感知），计入 `orm_pool_reconnects_total`。
  `idle_probe_s = 0` 关闭探测（只查本地状态）
- 关闭后归还的忙连接直接销毁
- 连接建立成功标记 health UP；失败标记 DOWN
- PostgreSQL 连接统一 UTF-8；MySQL 使用配置的 charset

### 8.4 观测：慢 SQL 日志与指标

- **慢 SQL 日志**：单条 SQL 执行耗时 ≥ `slow_query_ms`（默认 200，
  0 关闭）时由 `cboot.orm.pg` / `cboot.orm.mysql` logger 输出 warn，
  内容含耗时与 SQL 前 256 字符（不含绑定参数值）
- **指标**（`metrics::global()`，`GET /metrics` 暴露）：

| 系列 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `orm_pool_connections` | gauge | `dialect` / `state` | 池内 idle / active 连接数 |
| `orm_pool_reconnects_total` | counter | `dialect` | 借出前校验触发的重建次数（持续增长 = 网络不稳或池闲置被回收） |
| `orm_queries_total` | counter | `dialect` | 执行的语句数 |
| `orm_query_duration_ms` | histogram | `dialect` | 语句耗时（含绑定渲染与结果取回，不含行遍历） |

完整可运行示例见 [examples/orm](../examples/orm/README.md)。

## 9. 驱动实现

### 9.1 驱动接口

```cpp
using db_value =
    std::variant<std::nullptr_t, std::int64_t, double, std::string, bool>;

class statement {
public:
    virtual void bind(std::size_t index, const db_value& value) = 0;
    virtual bool next() = 0;
    virtual bool is_null(std::size_t column) = 0;
    virtual std::int64_t get_int(std::size_t column) = 0;
    virtual double get_double(std::size_t column) = 0;
    virtual std::string_view get_text(std::size_t column) = 0;
    virtual std::size_t column_count() const = 0;
    virtual std::string_view column_name(std::size_t column) const = 0;
    virtual std::size_t affected_rows() const = 0;
};

class connection {
public:
    virtual std::unique_ptr<statement> prepare(std::string_view sql) = 0;
    virtual void execute(std::string_view sql) = 0;
    virtual std::int64_t last_insert_id() = 0;
};

class DataSource {
public:
    virtual connection_lease acquire() = 0;
    virtual const dialect& dialect() const = 0;
};
```

### 9.2 PostgreSQL / libpq

- 使用 `PQexecParams` 文本格式：参数按文本传入，`nullptr` 表示 NULL
- 结果 `PQgetvalue` 文本读取；`PQgetisnull` 判断 NULL
- 错误检查 `PGRES_TUPLES_OK` / `PGRES_COMMAND_OK`
- 出错抛 `orm::error`，不回显密码
- 自增主键走 `RETURNING`，`last_insert_id()` 返回 0

### 9.3 MySQL / libmysql

- 使用文本协议：`bind` 保存参数，执行时用
  `mysql_real_escape_string` 转义后替换 `?`
- 结果通过 `mysql_store_result` 全量取回，`next()` 逐行前进
- 自增主键在 INSERT 后由 `mysql_insert_id` 回填
- 每线程通过 `mysql_thread_init` / `mysql_thread_end` 管理
- 错误信息来自 `mysql_error`，不包含密码

### 9.4 结果映射

- `SELECT` 列顺序与实体元数据一致
- `optional` 列 NULL → `nullopt`
- 非 optional 列 NULL → `orm::error`
- 整数/浮点/布尔文本转换失败 → `orm::error`
- 枚举按名字转换

## 11. 诊断

### 11.1 编译期

- `cboot.orm: entity requires exactly one [[=Id{}]] member`
- `cboot.orm: entity has multiple [[=Id{}]] members`
- `cboot.orm: entity has duplicate column name 'x'`
- `cboot.orm: unsupported entity member type`
- `cboot.orm: generated [[=Id{}]] must be an integer member`
- DSL 列类型不匹配：`column type and value type are not comparable`

### 11.2 运行期

- `cboot.orm: connection failed: ...`
- `cboot.orm: acquire connection timeout`
- `cboot.orm: unbound SQL parameter`
- `cboot.orm: extra SQL parameter`
- `cboot.orm: invalid integer column`
- `cboot.orm: unexpected NULL column`
- 更新/删除返回影响行数；0 行不默认抛异常

## 12. 安全

- PostgreSQL 值通过 `PQexecParams` 参数化，不拼接
- MySQL 值通过 `mysql_real_escape_string` 转义后进入文本 SQL；
  业务值不直接拼接
- 表名/列名只来自编译期注解/成员名
- 密码从环境变量/配置占位符读取，不写日志
- PostgreSQL 生产建议 `sslmode=require` 或更严格
- 原生 SQL 由调用方负责；ORM 不做字符串净化

## 14. 限制

- 同步调用；DB 阻塞会占用 worker 线程
- 事务支持单层；无嵌套事务 / savepoint / 隔离级别配置；MySQL DDL 会隐式提交
- 无关系映射、懒加载、identity map
- 无迁移工具；只有 `create_schema` / `drop_schema`
- 无复合主键、联合索引、乐观锁
- DSL 只覆盖单表常用查询；join/聚合/CTE 走原生 SQL
- 无批量插入 / COPY / 异步驱动 / LISTEN-NOTIFY
- 无 JSON/JSONB、数组、自定义 PostgreSQL 类型
- 枚举存 TEXT，不使用数据库 enum 类型
- MySQL 驱动使用转义文本协议，不是服务端预处理语句；
  `affected_rows` 语义为 MySQL 的 changed rows

## 15. 设计决策

| 决策 | 结论 |
|---|---|
| 用户侧风格 | 有界类型安全 DSL + 原生 SQL 逃生口 |
| 组件拆分 | 通用 `cboot.orm` + 驱动组件 `cboot.orm.postgres` / `cboot.orm.mysql` |
| 方言边界 | `orm::dialect` 负责标识符/占位符/类型/能力 |
| 自增主键 | PostgreSQL `RETURNING`；MySQL `last_insert_id` |
| 枚举存储 | `TEXT` / `TINYINT` 等逻辑类型映射 |
| 事务 | `EntityManager::transaction` + 固定连接的 `session` |
| schema | `Table{.name, .schema}`；MySQL 映射 database |
| 关系映射 | 不做 |
| 迁移 | 不做 |
| 条件表示 | 轻量 AST，执行时渲染 |
| 参数化 | PostgreSQL 服务端参数；MySQL 转义文本 |
| TIER | `contract` |

## 16. API 参考

### 16.1 实体注解

| 注解 | 位置 | 说明 |
|---|---|---|
| `orm::Table{.name, .schema}` | 类型 | 表名/schema；省略时用类型名、当前 schema |
| `orm::Column{"name"}` | 成员 | 列名覆盖；省略时用成员名 |
| `orm::Id{.generated}` | 成员 | 主键；`generated=true` 表示数据库自增 |

实体约束：aggregate、可默认构造、恰好一个 `Id`、成员类型受支持。

### 16.2 `orm::PgProps`

| 字段 | 默认 | 说明 |
|---|---|---|
| `url` | `postgresql://localhost/postgres` | URI 或 keyword=value conninfo |
| `user` | 空 | 覆盖 URL 中的用户 |
| `password` | 空 | 空/`${PGPASSWORD}` 时回退 libpq 的 `PGPASSWORD` |
| `sslmode` | `prefer` | URL 未指定时使用 |
| `pool_size` | 4 | 连接池大小 |
| `connect_timeout_s` | 5 | 建连超时（秒） |
| `acquire_timeout_ms` | 5000 | 取连接超时（毫秒） |
| `idle_probe_s` | 30 | 空闲多久后借出前探测（秒；0 关闭探测） |
| `slow_query_ms` | 200 | 慢 SQL 日志阈值（毫秒；0 关闭日志） |

### 16.3 `orm::MysqlProps`

| 字段 | 默认 | 说明 |
|---|---|---|
| `host` | `127.0.0.1` | 服务器地址 |
| `port` | `3306` | 端口 |
| `database` | `mysql` | 默认数据库 |
| `user` | `root` | 用户 |
| `password` | 空 | 空/`${MYSQL_PWD}` 时回退 `MYSQL_PWD` |
| `charset` | `utf8mb4` | 客户端字符集 |
| `pool_size` | 4 | 连接池大小 |
| `connect_timeout_s` | 5 | 建连超时（秒） |
| `acquire_timeout_ms` | 5000 | 取连接超时（毫秒） |
| `idle_probe_s` | 30 | 空闲多久后借出前探测（秒；0 关闭探测） |
| `slow_query_ms` | 200 | 慢 SQL 日志阈值（毫秒；0 关闭日志） |

两个配置类都使用前缀 `db`；同一应用只装配一个驱动。

### 16.4 `orm::EntityManager`

| 接口 | 说明 |
|---|---|
| `const dialect& dialect()` | 当前数据源方言 |
| `template<class T> std::optional<T> find(const id_type<T>&)` | 按主键查；未命中 nullopt |
| `template<class T> std::vector<T> all()` | 全表查询 |
| `template<class T> void insert(T&)` | 插入；自增 id 按方言回填 |
| `template<class T> std::size_t update(const T&)` | 按主键更新；返回影响行数 |
| `template<class T> std::size_t remove(const id_type<T>&)` | 按主键删除；返回影响行数 |
| `template<class T> void create_schema()` | `CREATE TABLE IF NOT EXISTS` |
| `template<class T> void drop_schema()` | `DROP TABLE IF EXISTS` |
| `template<class T> select_builder<T, EntityManager> select()` | DSL 查询入口 |
| `template<class T> update_builder<T, EntityManager> update()` | DSL 条件更新入口 |
| `template<class T> delete_builder<T, EntityManager> remove()` | DSL 条件删除入口 |
| `template<class F> transaction(fn)` | 单连接事务；正常提交、异常回滚 |
| `template<class T> std::vector<T> fetch_rows(sql, params)` | 低层查询；按 SELECT 列顺序映射 |
| `template<class T> std::vector<T> query(sql, params = {})` | 原生 SQL；按结果列名映射，支持 alias/join |
| `std::size_t execute(sql, params)` | 低层 DML/DDL；返回影响行数 |

`id_type<T>` 是实体 `Id` 成员的声明类型。
`entity_meta_v<T>` 是编译期元数据（表名/列名/主键）。

### 16.5 `orm::session`

事务内使用，固定一个连接：

| 接口 | 说明 |
|---|---|
| `dialect()` | 当前方言 |
| `find/all/insert/update/remove` | 与 EntityManager 相同的 CRUD |
| `select/update/remove` | DSL builder |
| `fetch_rows/query/execute` | 原生 SQL |
| `commit()` / `rollback()` | 手动结束事务；通常由 transaction 自动处理 |

`session` 不能跨线程，也不能在事务内重新调用 `EntityManager`。

### 16.6 DSL

列引用：

```cpp
orm::col<^^User::name>()
```

| 接口 | 说明 |
|---|---|
| `==` `!=` `<` `<=` `>` `>=` | 列与值比较；类型编译期检查 |
| `is_null(col)` / `is_not_null(col)` | SQL NULL 判断 |
| `in(col, range)` | `IN (?, ?, ...)`；空集合生成 `FALSE` |
| `like(col, pattern)` / `ilike(col, pattern)` | LIKE；ILIKE 在 MySQL 降级为 LOWER |
| `a && b` / `a \|\| b` / `!a` | 条件组合 |
| `asc(col)` / `desc(col)` | ORDER BY 项 |

`select_builder<T, Db>`：

| 方法 | 说明 |
|---|---|
| `where(condition)` | 设置 WHERE；后一次覆盖 |
| `order_by(order_term)` | 追加 ORDER BY |
| `limit(n)` / `offset(n)` | 分页 |
| `fetch()` | 返回 `std::vector<T>` |
| `fetch_one()` | 至多一行；无行返回 nullopt |

`update_builder<T, Db>`：

| 方法 | 说明 |
|---|---|
| `set(column, value)` | 追加 SET；类型编译期检查 |
| `where(condition)` | 必填 |
| `execute()` | 返回影响行数 |

`delete_builder<T, Db>`：

| 方法 | 说明 |
|---|---|
| `where(condition)` | 必填；防止误删全表 |
| `execute()` | 返回影响行数 |

### 16.7 驱动接口

| 类型 | 接口 |
|---|---|
| `orm::DataSource` | `connection_lease acquire()` / `const dialect& dialect()` |
| `orm::connection` | `prepare(sql)` / `execute(sql)` / `last_insert_id()` |
| `orm::statement` | `bind(i, value)` / `next()` / `is_null(col)` / `get_int` / `get_double` / `get_text` / `column_count` / `column_name` / `affected_rows()` |
| `orm::connection_lease` | RAII 归还连接；`operator->` 访问 connection |
| `orm::dialect` | 标识符/占位符/类型/自增/RETURNING/ILIKE 能力 |

### 16.8 错误

- 编译期：实体元数据/DSL 类型错误
- 运行期：`orm::error`，消息带连接/查询/映射错误
- 不打印连接串或密码

## 17. 与 JDBC / MyBatis / JPA 的定位

| 方案 | 业务代码 | 本组件 |
|---|---|---|
| JDBC | 手写 SQL + 手动映射 | 只在原生 SQL 逃生口 |
| MyBatis | 注解/XML 写 SQL + 自动映射 | 不作为主路径 |
| JPA/Hibernate | 实体 CRUD 自动 SQL | CRUD 部分对应 |
| jOOQ | 类型安全 DSL | 常用查询部分对应 |

定位：**实体 CRUD 自动 SQL + 有界类型安全 DSL + 原生 SQL 逃生口**，
不追求完整 ORM/JPA 能力。
